## 1. 要点（一言と、根拠の段階と、使いどころ）

再読に必要な期間を決め、会話の保存量を管理します。

根拠の段階：本体と公式で確認。

会話記録は、発言や道具の結果を残すファイルです。
cleanupPeriodDaysは、自動整理までの日数の設定です。
使うのは、ファイル一覧を読める対話モデルです。
推論型には用途から必要日数の案と理由を比較させます。
小型の指示追従型には、対象フォルダ、日付欄、集計欄を指定します。
どちらにも「本文は読まず、設定変更もしない」と具体的に渡します。
これは役割の分け方の案で、モデル間の優劣の実測ではありません。
保存期間の判断は、用途と必要な記録から人が行います。
過去の根拠の確認や、保存量の見積もりに向きます。

## 2. 仕組み（なぜ効くか）

記録が残っていれば、要約の元の根拠へ戻れます。
一方で、保存期間を延ばすほど記録量は増えます。
「長く残すほど良い」とは限りません。

[公式の自動整理の説明](https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically)では、既定30日、最小1日です。
0は無期限の意味ではなく、設定の検証エラーです。
対象には会話以外の計画や一部の作業記録もあります。
自動記憶のファイルには、別の保存規則があります。

会話記録は、読んだ本文や道具の結果を含む平文です。
この設定は、提供者側の保存期間を変えません。

## 3. 使い方（手順と例）

次は設定を変える前の設計手順です。

1. 何日前の記録まで必要か、用途を一文で決めます。
2. 利用画面と、現在の保持設定を確認します。
3. 記録本文を開かず、件数と容量を調べます。
4. 必要な記録と保存量を比べ、変更案を作ります。

```json
{
  "cleanupPeriodDays": 30
}
```

これは既定値を明示する例であり、今回は適用しません。
期限を短くすると、古い記録が自動整理の対象になります。
日数の変更で、既に消えた記録は復元できません。

DesktopとCoworkの会話には、別の保持設定があります。
組織の管理設定や版によっても条件が変わります。
使用中の版と公式の説明を照合して判断します。

## 4. 試し方（最初の一歩と測り方）

最初は30分の机上試行です。実際の会話を開かず、架空の一覧を使います。
作成から7日、25日、45日、70日、100日経った記録を各1件作り、
容量は順に1、2、3、4、5 MBとします。再読に必要な記録は前3件です。
10分で必要な保存日数と理由を書き、15分で30日・60日・90日の案を比較します。
試す人には架空一覧と必要な記録の条件、30・60・90日の候補だけを渡し、60日という正解と容量の採点表は最後の5分まで伏せます。
最後の5分で「必要な3件の保持数」と「残る容量」を計算し、採点表と照合します。
この例の成功基準は、必要な3件を3/3残し、容量を最小にする60日案を選べることです。
境界日の数え方や実際の整理処理は、この単純な練習では検証しません。
続いて実データで見積もる場合も、件数と容量だけで確認します。
削除や整理、設定変更は実行せず、これは試行案として扱います。
