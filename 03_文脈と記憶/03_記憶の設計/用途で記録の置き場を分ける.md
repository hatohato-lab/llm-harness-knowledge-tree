## 1. 要点（一言と、根拠の段階と、使いどころ）

使いどころは、以下のモデルの種類・指示の細かさ・向く作業で判断します。

記録を何に使うかで分け、次の作業の入口を作ります。

根拠の段階：元の出典で確認。

PARAは、案件、継続領域、資料、保管に分ける整理法です。
収集箱とは、まだ分類していない記録の置き場です。

短文分類を行う軽量モデルには、PARA四分類の定義と一例ずつを渡します。
「記録番号・置き場・理由」を返し、迷うものは未分類として別に残させます。
複数の用途を比較する推論型モデルには、今月の成果物と責任を渡します。
候補の比較を任せても、本文の複製禁止と参照先の提示は指定します。
これは割当案であり、特定モデルなら分類が正しいという保証ではありません。
調査メモや学習ノートを、成果物へつなげる作業に向きます。

## 2. 仕組み（なぜ効くか）

作業中の情報と、後で参照する情報を分けます。
すると、いま必要な範囲を選ぶ入口を作れます。
これは読取範囲を決める設計であり、分類だけの自動化ではありません。

[PARAの提唱者の説明](https://fortelabs.com/blog/para/)で四分類を確認しました。
この四分類を、この葉の基本の整理法とします。
保存記事は、収集箱、日次、成果物、仕組みを加えています。
追加の四区分は補助の試行例で、原著PARAの定義には含めません。
保存記事の投稿URLも、その拡張によるAIの精度向上も未確認です。
すべての記録に唯一の分類がある、と断定しません。

## 3. 使い方（手順と例）

1. 終了条件がある作業を「案件」に置きます。
2. 継続して守る責任や習慣を「継続領域」に置きます。
3. 再利用する背景知識を「資料」に置きます。
4. 活動を終えた記録は、参照用の「保管」に分けます。
5. 必要なら、未分類や日々の原文を置く補助の欄を別に作ります。

| 置き場 | 根拠の区分 | 独自の学習例 |
| --- | --- | --- |
| 案件 | PARA原著の四分類 | 今週作る比較レポート |
| 継続領域 | PARA原著の四分類 | 続けている読書の記録 |
| 資料 | PARA原著の四分類 | 要約方式の説明 |
| 保管 | PARA原著の四分類 | 終えた調査の原文 |
| 収集箱 | 保存記事を参考にした補助例 | まだ評価していない記事メモ |
| 日次 | 保存記事を参考にした補助例 | その日に決めたこと |
| 成果物 | 保存記事を参考にした補助例 | 完成した比較表 |
| 仕組み | 保存記事を参考にした補助例 | 分類基準と入口の目次 |

同じ本文を複製せず、別の用途からは参照します。
迷う記録は収集箱に残し、理由を短く書きます。
この知識の木を、今ここで別の構造へ移す指示ではありません。

## 4. 試し方（最初の一歩と測り方）

最初は50分で、PARA四分類と架空の十件を使う紙上試験にします。
準備15分で、各一〜二行の記録十件と、それを探す問い十問を作ります。
分類15分で、人が上の表の基本四分類から置き場を選び、入口の参照を決めます。
探索15分で、問いを順不同に読み、一問90秒以内で元の記録を探します。
集計5分で、到達数と、別の置き場を探し直した回数を数えます。
成功基準は90秒以内の到達9/10問以上、探し直し合計2回以下です。
失敗した問いの分類理由を見直し、必要なら区分をまとめます。
これは入口の使いやすさを調べる試験案で、AIの分類精度は未測定です。

## 5. 出典（公式・論文・元の記事までの道筋）

- 根拠の段階：元の出典で確認
- 公式・論文など：
  - [元の整理法：PARA](https://fortelabs.com/blog/para)
- 確認の限界：
  - 保存記事の来歴は、投稿URL未確認 → 保存記事 → PARA提唱者で止まっています。
  - このため、保存記事からの来歴には欠落があり、出典の道筋は未完了です。
  - 整理法はソフトの機能ではなく、確認すべき実行本体はありません。
  - 追加四区分の来歴や、AI製品の動作が確認できたという意味ではありません。
  - 記事にあるモデル名、価格、性能は未確認です。
  - ほかにも、確認できていない点が複数あります。
