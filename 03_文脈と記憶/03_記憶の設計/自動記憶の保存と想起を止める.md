## 1. 要点（一言と、根拠の段階と、使いどころ）

自動記憶を使わない時は、保存と読出しを設定で止めます。

根拠の段階：公式で確認。

想起とは、保存した情報を次の判断へ取り出すことです。
autoMemoryEnabledは、自動記憶の有効設定です。

設定ファイルを読めるエージェント型モデルで、適用範囲を点検します。
推論型にも軽量型にも「対象範囲・変更キー・変更前後・確認方法」を指定します。
道具のない会話型には設定案のレビューを頼み、適用済みとは答えさせません。
過去の自動記憶を使う条件と使わない条件を分ける比較試験に向きます。
モデルが抽象的な禁止文に従うかと、設定によって機能を停止するかは分けて扱います。

## 2. 仕組み（なぜ効くか）

自動記憶を無効にすると、その読込みと書込みを止めます。
保存済みファイルの削除や、手動記録の禁止とは別です。

公式は、設定値falseと無効化用の環境変数を案内します。
環境変数とは、起動する処理へ渡す名前付きの設定です。
[公式の無効化方法](https://code.claude.com/docs/en/memory#enable-or-disable-auto-memory)を確認しました。

子担当の記憶設定も、自動記憶が無効なら働きません。
[公式の子担当の記憶](https://code.claude.com/docs/en/sub-agents#enable-persistent-memory)に明記されています。
外部の記憶製品まで停止するとは限りません。

## 3. 使い方（手順と例）

1. 全作業か、一つの案件か、停止する範囲を決めます。
2. 既存の設定を保ち、変更するキーだけを選びます。
3. 適用前後の差分を記録します。
4. 新しい会話で、無効表示と保存先を点検します。
5. 外部の記憶製品は、別の設定として確認します。

次は設定の仕組みを示す例です。今回は未適用です。

```json
{ "autoMemoryEnabled": false }
```

この値で、常設指示のCLAUDE.mdまで消えるわけではありません。
設定フォルダ全体を消す必要はありません。

## 4. 試し方（最初の一歩と測り方）

最初は30分で、実際には適用しない設定案を点検します。
10分で架空の設定に「全案件を停止」「一案件だけ停止」「保存済みファイルは残す」の3ケースを書き、各ケースの変更範囲と期待値を付けます。
次の10分で[公式の無効化方法](https://code.claude.com/docs/en/memory#enable-or-disable-auto-memory)と照合し、最後の10分で採点します。
合格は対象範囲と値の一致3/3件、無関係な設定変更0件、ファイル削除案0件です。
後日の実機試験では無効表示と新規記憶書込み数も記録します。今回は設定案の試験であり、停止動作や回答品質を実測していません。
「記憶は常に誤りを生む」という因果は未確認です。
