## 1. 要点（一言と、根拠の段階と、使いどころ）

使いどころは、以下のモデルの種類・指示の細かさ・向く作業で判断します。

規則の意味を考える前に、設定の書き損じを機械で探します。

根拠の段階：元の出典で確認。

推論を重ねるモデルと小型で高速なモデルの両方へ渡す設定を点検します。
検査自体はモデルを呼ばず、選んだ検査規則を適用します。
指示は、対象ファイルと検査する書式を具体的に指定します。
規則や手順書が増え、同じ形式の不備を繰り返す時に使います。

## 2. 仕組み（なぜ効くか）

静的検査とは、指示を実行せずに書式の不備を調べる方法です。
agnixは、指示ファイルや設定を調べる外部製の検査器です。

書式の不備で条件が読まれないと、文章の改善だけでは直りません。
機械の検査は、同じ規則を繰り返し適用できます。
指摘に番号と位置があれば、修正した理由を追えます。
この仕組みは、[作者の検査規則一覧](https://agent-sh.github.io/agnix/docs/rules/)と[CLIの公開実装](https://raw.githubusercontent.com/agent-sh/agnix/main/crates/agnix-cli/src/main.rs)で確認できます。

検査器には、必須の書式と文章への助言が混在します。
警告が出たことと、Claude Codeが動かないことは別です。
日本語の意味の矛盾や、本人の意図は別に確かめます。
検査器の作者文書と、現行のClaude Code仕様を照合します。

## 3. 使い方（手順と例）

1. 点検したい一枚と、期待する読込み条件を決めます。
2. 設定欄、参照先、循環した参照を調べます。
3. 指摘番号、行、根拠、修正候補を記録します。
4. 検査器の助言を、現在の公式仕様と比べます。
5. 採用した修正の後、実際の読込みも確かめます。

YAMLは、項目名と字下げで設定を表す書式です。
次は、書式の点検に使える独自の比較例です。

```yaml
# コロンを含む値は、引用符で囲む。
description: "Do this: compare two rules"
```

機械試験は、agnixが既に導入された練習環境で行います。
未導入の場合は公開規則との手作業の照合までとし、機械の成功には数えません。
検査器を使う場合も、修正前に差分を確認します。
警告を消すためだけに、必要な禁止事項を削りません。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は40分の機械試験案です。agnixが導入済みで、ローカルの架空試料を検査できることが前提です。
準備10分、二枚の検査10分、診断との照合15分、記録5分に分けます。
検査するのは、[作者の検査規則](https://agent-sh.github.io/agnix/docs/rules/)にある必須descriptionの欠落（AS-003）一件です。
正常試料は `good/text-checker/SKILL.md` として、次の全文を用意します。

```text
---
name: text-checker
description: Check spelling in supplied text when the user asks for a spelling review.
---
# Text checker
Read the supplied text and list spelling corrections.
If no correction is needed, return no corrections.
```

同じ本文を `bad/text-checker/SKILL.md` にも置き、descriptionの一行だけを外します。
両方とも親フォルダ名はtext-checkerにそろえ、別の不備を混ぜません。
[作者のJSON出力仕様](https://agent-sh.github.io/agnix/docs/configuration/#cli-flags)に従う検査案です。

```text
agnix --format json good/text-checker/SKILL.md
agnix --format json bad/text-checker/SKILL.md
```

自動修正は指定せず、二つの実行の診断、終了コード、利用版を別々に残します。
成功は実行完了2/2件、欠落の検出1/1件、正常試料へのAS-003誤検出0/1件です。
不備を報告して非ゼロ終了した検査も実行完了に数えますが、起動失敗とは区別します。
ほかの規則の警告は別欄へ記録し、この一規則の成功を全体の精度へ広げません。
未導入、規則が無効、起動失敗、時間切れは未実行として残し、合格にしません。
手作業の照合は準備です。今回、本体試験も導入も実行していません。

## 5. 出典（公式・論文・元の記事までの道筋）

- 根拠の段階：元の出典で確認
- 公式・論文など：
  - [作者リポジトリ](https://github.com/agent-sh/agnix)
  - [作者の公式検査規則](https://agent-sh.github.io/agnix/docs/rules)
  - [agnix本体のCLI実装](https://raw.githubusercontent.com/agent-sh/agnix/main/crates/agnix-cli/src/main.rs)
  - [公式の冒頭設定仕様](https://code.claude.com/docs/en/memory#rule-frontmatter-reference)
  - [設定方法](https://agent-sh.github.io/agnix/docs/configuration)
- 確認の限界：
  - 公開実装の静的確認であり、このPCでの実行結果ではありません。
  - 検査機能と、一部の自動修正機能を確認しました。
  - この調査の実行検証はありません。
  - 元のURLがない投稿は、対応先が未確認です。
  - 照合した公式資料は、投稿のリンク先と同じとは限りません。
  - ほかにも、確認できていない点が複数あります。
