## 1. 要点（一言と、根拠の段階と、使いどころ）

使いどころは、以下のモデルの種類・指示の細かさ・向く作業で判断します。

依頼文だけで完結する子担当には、常設指示の投入を絞ります。

根拠の段階：公式で確認。

推論を重ねるモデルでも、小型で高速なモデルでも、依頼文だけで完結する子担当を対象にします。
指示には入力、必要な制約、表記を調べる順序、返す形式まで書きます。
渡した短文の整形や分類など、狭い作業に向きます。

## 2. 仕組み（なぜ効くか）

子担当とは、親から一部の作業を任されるモデルです。
常設指示とは、会話の開始時に読み込む共通の指示です。
omitClaudeMdは、子への常設指示の投入を省く設定です。

必要な材料が依頼文にそろえば、共通指示の重複を減らせます。
投入範囲の根拠は、[公式の開始時の情報](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup)です。
ただし、必要な規則まで外すと、作業の条件が欠けます。
読む量と守る条件の両方を確認する設計です。
省略による速度や品質の改善幅は未確認です。

親の履歴を引き継ぐ分岐方式は、別の仕組みです。
この設定は、会話履歴の完全な消去を意味しません。
後からファイルを読む権限も、この設定だけでは制限しません。

## 3. 使い方（手順と例）

1. 依頼文と入力だけで完結する仕事を選びます。
2. 必要な口調、対象範囲、禁止事項を依頼文へ書きます。
3. 子担当の定義へomitClaudeMd: trueを加える案を作ります。
4. 設定ありと設定なしで、同じ入力を比較します。
5. 条件の欠落があれば、依頼文か分担の境界を直します。

次は独自の練習案です。実行した定義ではありません。

```yaml
---
name: text-checker
description: 渡された短文の表記を点検する
tools: []
omitClaudeMd: true
---
渡された本文だけから、表記の修正候補を三件以内で返す。
修正が不要なら、修正なしと返す。
不明な事実は補わない。
日本語で返し、ファイルを読み書きしない。
```

対応はClaude Code 2.1.271以降です。
主会話を--agentで起動した場合、この欄は無効です。
通常の子担当では、組織が配る管理指示は残ります。
組織が配る子担当定義には、別の扱いがあります。
ExploreとPlanは、既定で常設指示の自動投入を省きます。

## 4. 試し方（最初の一歩と測り方）

既に子担当を使える環境で、45分以内に行う試行案です。
準備10分、六試行を各3分以内、採点と記録17分とします。
各短文に既知の誤記を一件ずつ入れ、正解表を先に作ります。
合格は省略ありで正しい修正3/3件、不要な修正0件、条件違反0件です。
省略なしとの正答数も比較し、品質が悪化した場合は採用しません。
起動できない場合や時間切れは未実行欄に残します。

架空の短文を三本用意し、両条件で表記を点検します。
正しい修正、不要な修正、条件違反を数えます。
入力の使用量は、品質の採点と分けて残します。
親が代わりに答えた結果を、子の結果に混ぜません。
子へ渡った入力と、子が返した結果を照合します。
