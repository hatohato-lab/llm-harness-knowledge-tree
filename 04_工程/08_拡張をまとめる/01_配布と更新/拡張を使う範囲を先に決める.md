## 1. 要点（一言と、根拠の段階と、使いどころ）

自分だけか、チーム全体かを決めてから拡張を導入します。

プラグインは、追加部品をまとめた配布単位です。
適用範囲は、設定が効く利用者と作業場所の組です。

使いどころ：範囲の照合は軽いモデルに向きます。
共有方針の判断には、賢いモデルを使います。
対象者、フォルダ、設定ファイルを具体に指示します。
複数の仕事場で、別々の拡張を使う場面に向きます。

根拠の段階：公式で確認

## 2. 仕組み（なぜ効くか）

[公式の導入範囲](https://code.claude.com/docs/en/discover-plugins#choose-an-install-scope)は、個人、共有プロジェクト、局所の範囲を分けます。
局所設定は、その仕事場の自分だけに効きます。
そのため、試用の影響をほかの仕事場と分けられます。
ただし、範囲指定は権限を隔離する仕組みではありません。

| 指定 | 適用先 |
| --- | --- |
| user | 同じPC上の自分の全プロジェクト |
| project | 同じプロジェクトの共同作業者 |
| local | 同じプロジェクトの自分だけ |

共有設定の記録だけでは、各PCへの取得は終わりません。
有効化、実体の取得、読込みを分けて確認します。

## 3. 使い方（手順と例）

1. 使う人と仕事場を一行で書きます。
2. 既存設定が効く範囲を確認します。
3. 最初の試用は、対象を一つの仕事場へ絞ります。
4. 導入後に、実際の設定先と部品一覧を照合します。
5. 共有する段階で、各利用者の取得手順もそろえます。

例：文書整理の拡張は、文書用の仕事場だけで試します。
別の開発用の仕事場へ波及していないか確認します。
今回は導入も設定変更もしていません。

## 4. 試し方（最初の一歩と測り方）

準備込み35分の紙上試行です。実際の導入や設定変更はしません。
最初の10分で、自分と共同作業者の2人、各自のPC上にある作業場AとBの2か所を書いた4マスの表を作ります。
次の15分で、自分がAで導入する設定を想定し、user・project・localの3種類それぞれに適用先を書きます。
設定の重複や管理者設定がない条件で、userは自分のA・B、projectは2人のA、localは自分のAだけが正解です。
残り10分で公式の範囲表と照合します。成功条件は12マス中12マス正解、対象外を有効とした誤り0件です。
正解数、誤り数、所要分数を記録します。これで確かめるのは範囲の判断で、実機の権限隔離や読込み成功は別の試験です。試行は未実行です。
