## 1. 要点（一言と、根拠の段階と、使いどころ）

作業を分ける前に、渡す物と受け取る物をそろえます。

入出力の約束は、受渡し形式と意味を定めた記録です。

根拠の段階：公式で確認

公式の調査事例は、出力形式と作業境界を指定します。
個々の約束だけによる改善量は未確認です。

使いどころは、調査、分類、実装などの引渡しです。
賢いモデルには、約束の不足を点検させます。
軽いモデルには、項目名と返却例を具体的に渡します。
抽象的な目的に加え、境界部分を具体化します。

## 2. 仕組み（なぜ効くか）

前の担当の成果が、次の担当の入力になります。
項目名や単位が違えば、内容が正しくても使えません。
受け手が推測せずに済むよう、境界の意味を固定します。
この説明は、工程設計からの推論です。

[Anthropicの分担事例](<https://www.anthropic.com/engineering/multi-agent-research-system>)は、目的と出力形式を明示します。
[計画の原文](<https://raw.githubusercontent.com/obra/superpowers/main/skills/writing-plans/SKILL.md>)は、作業間の名称と型の一致を扱います。

DSPyは、AIを呼ぶ工程を部品として組む開発基盤です。
[DSPyの開発元文書](https://raw.githubusercontent.com/stanfordnlp/dspy/main/docs/docs/learn/programming/signatures.md)は、入力と出力の意味を宣言します。
ここでは、指示文の自動最適化とは分けて考えます。

## 3. 使い方（手順と例）

1. 入力資料と、利用してよい範囲を指定します。
2. 出力の項目、形式、置き場所を決めます。
3. 空欄、不明、失敗の表し方を決めます。
4. 受け手が必要とする一例で、意味を確かめます。
5. 約束が変われば、関係する作業へ反映します。

公開資料の分類なら、次の約束が使えます。

| 項目 | 約束の例 |
| --- | --- |
| 入力 | 公開資料の題名と本文 |
| 出力 | 資料番号、分類、理由、出典 |
| 不明 | 分類は「未確認」とし理由を書く |
| 失敗 | 読めない資料の番号と「読込失敗」を返す |
| 境界 | 分類名は共通の一覧から選ぶ |

これは独自例です。
通常と不明の返却では、資料番号・分類・理由・出典の4項目を必須にします。
読込失敗の場合だけは、資料番号と状態「読込失敗」の2項目を必須とし、分類・理由・出典は省略できます。
返却先が文章を読むか、プログラムかで形式を選びます。
処理の細部まで固定する必要はありません。

## 4. 試し方（最初の一歩と測り方）

紙か手元のメモ帳で、準備10分、返却見本の作成15分、受取り点検10分、記録5分の計40分で試します。
外部サービスやAIの呼出しは使わない、独自の受渡し練習です。

1. 架空の資料を3件作ります。分類できる資料、分類不明の資料、本文を読めない資料を各1件にします。
2. 上の表を使って、通常・不明・失敗の返却見本を各1件作ります。
3. 約束の表だけを見て、受け手として資料番号と状態を読み取ります。補足が必要な箇所も数えます。

事前の合格条件は、資料番号と状態を3件中3件正しく読み取れ、状態別の必須項目が計10項目中10項目そろい、名称の食い違い・補足を要する箇所がそれぞれ0件です。
不合格なら約束か返却例を1回直し、同じ3件を再点検します。
出力が整っていても、実資料の分類が正しいことやAIの成功率は、この紙上試行だけでは分かりません。
