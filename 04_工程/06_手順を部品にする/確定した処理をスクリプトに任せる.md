## 1. 要点（一言と、根拠の段階と、使いどころ）

判断は文章で伝え、同じ計算や変換は実行部品へ分けます。

スクリプトは、決めた処理を実行する小さなプログラムです。
スキルは、必要な作業で呼び出す手順の部品です。

根拠の段階：公式で確認

使いどころは、件数集計、並べ替え、形式検査などです。
推論を重視するモデルには、処理を分ける理由と境界を渡します。
高速・軽量のモデルには、入力、実行方法、結果の読み方を渡します。

## 2. 仕組み（なぜ効くか）

同じ計算を毎回文章で作り直す必要が減ります。
入力を固定すれば、結果を繰り返し照合できます。
ただし、プログラムの誤りまで消えるわけではありません。

公式は、スキルへ実行用コードを含める設計を示します。
並べ替えなどをコードへ任せる理由も説明しています。
[Agent Skillsの実行処理](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)が根拠です。

Voyagerは、成功した実行コードを再利用する研究です。
対象はMinecraftで、Claudeの文書形式とは別物です。
再利用の設計原理だけを、仕事へ応用する候補にします。

## 3. 使い方（手順と例）

1. 毎回同じ規則で行う小処理を一つ選びます。
2. 入力形式と、正しい出力の例を決めます。
3. 判断の文章と、実行処理を別ファイルへ分けます。
4. 手順には、実行するのか読むのかを明記します。
5. 実行結果と失敗の扱いを、手順へ戻します。

~~~text
手順：公開メモの見出し一覧を作る。
実行部品：見出し行を取り出し、件数を返す。
AIの判断：重複や分類の候補を説明する。
失敗時：結果を補わず、入力とエラーを示す。
~~~

成功コードの保存には、入力条件も添えます。
環境や道具の版が違えば、同じ結果とは限りません。
検査をどう設計するかは、05_評価と改善で扱います。

## 4. 試し方（最初の一歩と測り方）

変更を伴わない件数集計を選びます。
人が数えた小さな入力を、正解として用意します。
結果の一致、実行時間、手直し回数を比べます。
今回は実行部品の作成や導入はしていません。

**最初の一歩は、準備込み45分のローカル集計です。**
10分で、見出しが2行の正常入力、空入力、本文中に#を含むだけの入力を文字列で用意します。
15分でPowerShellの文字列配列を行頭の「# 」で絞り、件数を数える小処理を組みます。
10分で3入力を各2回実行し、人の正解（2、0、0）と照合します。ファイルは読み書きしません。
最後の10分で、結果6/6一致、同一入力の結果の差0件を合格条件として記録します。
実行秒数と手直し回数も残します。これは今後の無料の試行案で、コードの全入力への正しさや時間短縮は未確認です。

小処理の草案は次です。期待する出力は順に2、0、0です。

~~~powershell
$cases = @("# A`n# B`n本文", "", "本文に # を含む")
$cases | ForEach-Object {
    @($_ -split '\r?\n' | Where-Object { $_ -match '^# ' }).Count
}
~~~
