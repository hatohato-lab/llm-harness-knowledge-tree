## 1. 要点（一言と、根拠の段階と、使いどころ）

作りたい成果と使える環境から、専門手順を一つ選びます。

スキルは、必要な作業で呼び出す手順の部品です。
依存ツールは、その手順を動かすために必要な道具です。

根拠の段階：公式で確認

使いどころは、文書形式や専門分野で作法が違う作業です。
推論を重視するモデルには、目的と手順を選ぶ理由を求めます。
高速・軽量のモデルには、選んだ手順と具体的な入力を渡します。
公式確認は、専門手順を選べる仕組みの範囲です。
個別の外部スキルの効果を、一括で認定していません。

## 2. 仕組み（なぜ効くか）

専門手順には、その成果物に固有の作法を置けます。
完成形から選ぶと、関係のない手順を混ぜにくくなります。
道具や入力が合わなければ、有名な手順でも使えません。

Anthropicは、文書形式別などの手順を公開しています。
[公式のスキル集](https://github.com/anthropics/skills)で確認しました。
第三者の性能値は、対象と比較条件が限定された報告です。
私の業務での再現は未確認です。

## 3. 使い方（手順と例）

1. 納品形式と、完成後にできることを書きます。
2. 候補の本文を読み、用途と対象外を確かめます。
3. 入力形式、依存ツール、利用条件を確かめます。
4. 必要な手順を一つ選び、選んだ理由を書きます。
5. 小さな例で、対象に適合するか確認します。

| 作業 | 候補の例 | 選ぶときの条件 |
|---|---|---|
| 文書を作る | docx、pdf、pptx、xlsx | 必要な納品形式 |
| 画面を設計する | frontend-design、Taste | 用途と見た目の制約 |
| 仕組みを説明する | show-me | 説明する関係と出典 |
| データを調べる | Supabase、SciAgent-Skills | 対象分野と道具 |
| 事業案を考える | minimalist-entrepreneur | 現在の検討段階 |
| Claudeの利用コードを更新する | claude-api | 対象ファイルと移行目的 |

この表は候補の分類で、導入の推奨順位ではありません。
文書を描画する等の検査方法は、05_評価と改善で扱います。
外部への接続は、手順があるだけでは利用できません。

## 4. 試し方（最初の一歩と測り方）

公開可能な短い入力と、必要な完成形を用意します。
候補一つについて、前提が満たせるか表にします。
試す場合は、使わない場合との修正時間を比べます。
読み違い、欠落、道具不足も数えます。
人気、収録数、作者の成績だけでは決めません。

**最初の一歩は、準備込み40分の選択点検です。**
10分で「Wordの1ページ案内」「PDFの文章抽出」「納品形式が未指定」の3依頼を作ります。
20分で公式のdocxとpdfの本文を読み、形式・用途・必要な道具・対象外の4欄を埋めます。
最後の10分で、選択結果がdocx、pdf、確認待ちの3/3一致、4欄×2候補の記入8/8、根拠のない道具利用可の断定0件なら合格です。
手順の選び方だけを無料で確かめる試行案です。導入、生成、描画は行わず、修正時間の削減は未測定です。
