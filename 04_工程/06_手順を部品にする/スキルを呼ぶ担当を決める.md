## 1. 要点（一言と、根拠の段階と、使いどころ）

人が開始する手順と、AIが選ぶ手順を分けます。

スキルは、必要な作業で呼び出す手順の部品です。
先頭設定は、SKILL.mdの冒頭に置く設定欄です。
プラグインは、手順や設定をまとめて配る部品です。

根拠の段階：公式で確認

使いどころは、長い点検や専門手順の呼び分けです。
推論を重視するモデルにも、起動の条件は具体的に書きます。
高速・軽量のモデルでは、人による名前指定から始めます。

## 2. 仕組み（なぜ効くか）

人が時点を決めれば、開始の判断が曖昧になりません。
AIの選択には、用途を説明する短い文が必要です。
呼出しの設定は、作業品質を保証しません。

[公式の呼出し制御](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)は次を区別します。

| 設定 | 人が呼ぶ | AIが自動で呼ぶ |
|---|---|---|
| 既定 | 可 | 可 |
| disable-model-invocation: true | 可 | 不可 |
| user-invocable: false | 不可 | 可 |

allowed-toolsは、道具の事前許可を加える設定です。
使える道具をその一覧だけに絞る意味ではありません。

## 3. 使い方（手順と例）

1. 手順ごとに、開始を決める人を一つ選びます。
2. 人が開始するなら、手動専用の設定を検討します。
3. 自動選択するなら、用途と対象を説明文へ書きます。
4. 手順の入口で、入力不足の場合を扱います。
5. 名前を指定した場合と、自然文の場合を分けて確かめます。

~~~yaml
name: source-note
description: 指定された資料の主張と出典を整理する。
disable-model-invocation: true
~~~

実行名は「/source-note」です。
「/skills」は一覧と管理で、個別手順の実行名ではありません。

Gitは、ファイルの変更履歴を管理する道具です。
コミットは、Gitへ変更を記録する操作です。
2.1.286以降には、verify等を直前に促す仕組みもあります。
開始時の配置、AIからの呼出し可否などが条件です。
組込み版やプラグイン版は、この連動の対象外です。
文書だけ、試験だけの変更も除外されます。
これは指示の追加であり、実行の強制ではありません。
条件は[公式の説明](https://code.claude.com/docs/en/skills#run-your-checks-before-each-commit)を参照します。

## 4. 試し方（最初の一歩と測り方）

公開資料を読むだけの小手順で試します。
名前指定、関連する自然文、無関係な依頼を用意します。
開始したかと、正しい結果だったかを別々に記録します。
例の設定は学習用で、今回は登録していません。
呼ぶべき依頼の呼出し率と、不要な呼出しの件数を測ります。

**最初の一歩は、準備込み40分の紙上点検です。**
10分で上の3設定と、名前指定・関連する自然文・無関係な依頼の3入力を用意します。
20分で9通りの期待動作を表にし、公式の呼出し表と照合します。
9通りは設定を当てはめる練習です。合否は次の「人とAIの可否」6枠だけで判定します。
自然文での実際の選択は予測せず、設定上の「許可／禁止」と区別します。
最後の10分で、設定による可否6枠（3設定×人とAI）を採点します。
成功条件は6/6一致、手動専用をAIの自動起動可とした誤り0件です。
登録もAIの呼出しもせず、設定の理解を確かめる試行案です。実際の起動率と品質は未測定です。
