# 例なしで始めて不足した例を足す

## 1. 要点（一言と、根拠の段階と、使いどころ）

明確な指示だけで試し、実際の不足に合う例を足します。

- 根拠の段階：公式で確認
- 対象は、指示に従う対話型の言語モデルです。
- 知識作業向けのモデル（Claude Opusなど）では、目的・条件・出力形式を指定して始めます。
- 速度重視のモデル（Claude Haikuなど）では、分類名や禁止事項も一行ずつ明示して比較します。
- どちらも、間違いが残った条件にだけ具体例を足す試行案です。モデル間の効果差は未測定です。
- 使いどころ：慣れた分類や要約など、成功条件を決めやすい作業に向きます。

モデルの位置づけは[公式のモデル一覧](https://platform.claude.com/docs/en/models/overview)に基づきます。
指示の分け方は、この葉で試す設計です。

例なし提示とは、見本を付けずに作業を指示する方法です。
英語では zero-shot prompting と呼びます。

## 2. 仕組み（なぜ効くか）

モデルが既にできる部分に、毎回見本を足す必要はありません。
最初の結果を見ると、例で補うべき不足を特定できます。
規則が不足したのか、出力形式が違うのかを分けられます。

Anthropicは、最小限の指示を強いモデルで試すと述べます。
その失敗に合わせ、指示や例を加える方針です。
[公式の文脈設計記事](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

最小限とは、作業に必要な条件を省く意味ではありません。
例なしが常に高品質という主張でもありません。
モデル別にどこまで省けるかは、試して確かめます。

## 3. 使い方（手順と例）

1. 目的、入力、望む出力、守る条件を書きます。
2. 例を付けず、小さな代表課題で結果を見ます。
3. 間違いを一つ選び、対応する例だけを加えます。
4. 例に使わなかった課題で、改善を確かめます。

最初の指示は、次のようにします。

~~~text
次の学習メモを、初心者向けの一文に要約する。
専門語は日常語に直し、原文にない主張は加えない。
出力は要約だけにする。
入力：ここに学習メモを置く。
~~~

毎回「以下に要約します」が付く場合を考えます。
まず「前置きは付けない」と具体化します。
それでも続くなら、短い入力と要約だけの例を添えます。
これは試行案であり、実際の失敗記録ではありません。

例は、足した理由を言えるものに絞ります。
既知の厳密な形式がある場合は、最初から見本を使えます。
「例なしから」は、見本が必要な仕事を妨げる規則ではありません。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は50分の比較です。以下の時間・件数・合格値は、この葉の試行案で、実測値ではありません。

1. 準備10分：短い架空の学習メモを12件作り、調整用6件と確認用6件に固定します。各件で「一文・前置きなし・原文にない事実なし」の3条件を採点表にします。
2. 調整10分：例なし版で調整用6件を試し、失敗を一つ選び、その失敗を補う入出力例を1件だけ足します。失敗が0件なら例なし版を残して終了します。
3. 比較20分：例なし版と一例追加版を、それぞれ確認用6件に使います。同じモデル・設定・入力を使い、会話は各件で分け、確認用の答えは例に転用しません。
4. 採点10分：3条件を全て満たした件数を6件中何件かで数え、原文にない事実の数と指示全文の文字数も記録します。

仮の採用条件は、追加版の成功が5/6件以上、例なし版より1件以上多く、事実の追加が0件であることです。
両版とも6/6件なら、例なし版を残します。それ以外は採用を保留し、残った失敗を記録します。
50分で終わらなければ未完了と記録します。今回の点検ではモデルへの入力も採点も実行していません。
