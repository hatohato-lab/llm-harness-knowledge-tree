## 1. 要点（一言と、根拠の段階と、使いどころ）

目的と制約を明確にし、手順の細かさをモデルに合わせる。

モデルは、回答を作るAIの種類を指す。
抽象的な指示は、結果を指定して手段を任せる指示を指す。
具体的な指示は、操作の順や判断条件まで指定する指示を指す。

- 根拠の段階：公式で確認
- 推論型には、目的・制約・完成条件を渡して手順を任せる。
- 通常型や軽量型では、3〜5手順と判断条件を足す案を比べる。
- 使いどころ：設計案の比較には前者、定型分類には後者を試す。
- どちらでも、完成条件と守る制約は具体的にする。

「賢ければ抽象、軽ければ具体」は普遍法則ではない。
モデルの大小に加え、訓練の違いと作業内容が関わる。

## 2. 仕組み（なぜ効くか）

推論型モデルは、回答前に内部で検討するよう訓練された型を指す。
[OpenAIの指示設計](https://developers.openai.com/api/docs/guides/prompt-engineering#prompting-reasoning-models)は、推論型へ目標を渡す使い方を説明する。
同資料は、通常型には実行方法の明示が役立つと説明する。
これは全社の大小モデルを二分する規則ではない。
軽量型への3〜5手順は、この葉の比較案であり公式の数値ではない。

[Anthropicの公式指針](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#be-clear-and-direct)も、明確な制約と出力形式を勧める。
順序や抜けの防止が重要なら、手順を列挙する方針である。
強いモデルにも、読み手の事情や業務固有の規則は必要だ。

手順を任せると、解き方を選ぶ余地が残ると考えられる。
手順を示すと、選択肢や曖昧さを減らせると考えられる。
この二つは仕組みの解釈であり、効果の保証ではない。
[推論型への公式指針](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively)は、簡潔な指示と明確な完成条件を勧める。
したがって、手順の裁量を残しても完成条件は省かない。

目的の具体度と、手順の具体度は別々に考えます。
目的が明確なら、方法をすべて固定する必要はありません。
不適切な手順は、かえって遠回りになる場合もあります。
自由な発想では、最初から形式を絞らない案も試せます。

## 3. 使い方（手順と例）

1. 目的、入力、完成条件、制約を先に書く。
2. 正しい手順が既知なら、その順を示す。
3. 解き方も考えてほしいなら、手段の裁量を残す。
4. 誤りが出た箇所だけ、条件や例を追加する。

同じ読書メモを整理する場合の例を示す。

目的中心の指示例：

```text
このメモから、初心者向けの読む順番を提案してください。
前提知識のつながりを重視してください。
5冊までに絞り、各冊を選んだ理由を1文で書いてください。
選ぶ手順は任せます。資料にない書名は足さないでください。
判断材料がない本は「前提未確認」としてください。
```

手順中心の指示例：

```text
1. メモにある書名だけを抜き出してください。
2. 各本の前提知識を、メモの記述だけで確認してください。
3. 前提が少ない本から、最大5冊を並べてください。
4. 書名と選んだ理由を1文ずつ返してください。
5. 判断材料がない本は「前提未確認」としてください。
```

軽いモデルでも、全手順を長く書けばよいわけではない。
細かい指示同士が矛盾すれば、別の誤りを生む。

記事を比較する時も、同じ条件で裁量だけを変えられます。
次は、統合元にあった比較例を短くしたものです。

```text
共通条件：二つの記事を比べてください。
結論、根拠の場所、未確認点を各一つ書いてください。
任せる版：重要な違いが伝わる方法を選んでください。
手順版：主張を抜き出し、条件と根拠を対応させてください。
その後、同じ点と違う点を分けて結論を書いてください。
```

## 4. 試し方（最初の一歩と測り方）

次は、この葉で提案する50分の検証案である。
実際の比較は、利用と費用を許可された環境で後日行う。

1. 準備10分：正解が分かる短い読書メモを3件用意する。
2. 各メモに、完成条件3つと「足してはいけない事実」を書く。
3. 目的中心版と手順中心版を作り、完成条件を同じにする。
4. 比較20分：同じモデルで各3件、計6回答を得る。
5. 採点と手直し15分：最初の5分で完成条件を各0/1点、1案9点満点で採点し、資料にない事実を数える。
   残りは各案5分を上限に手直しし、時間を測る。採点は手直し前の回答に対して行う。
6. 記録5分：各案の得点、追加された事実の件数、手直し時間を並べて比べる。

同じモデル名・版・設定を使い、各回答は新しい会話で得る。
回答は各200字以内とし、違いを手順の細かさに限る。
20分で6回答が揃わなければ、試行未完了と記録する。
成功条件は、9/9点、事実の追加0件、手直し合計5分以内。
手直し合計は1案の3回答分で、5分以内に終わらなければ不合格とする。
両案が成功したら、手直し時間が短い案を次の候補にする。
得点が同じなら、内容の正確さの改善は未検出と記録する。
手直し時間の差は、内容の点数と分けて記録する。
この基準は検証用の仮置きで、一般的な性能保証ではない。
別モデルの比較は次回に分け、同じ3件と採点表を再利用する。
文章の長さや好みの文体だけで、指示の良し悪しを決めない。
