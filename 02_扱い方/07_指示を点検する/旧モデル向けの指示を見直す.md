## 1. 要点（一言と、根拠の段階と、使いどころ）

モデルは、文章を受け取って答えを作るAIの中核です。
回避策は、あるモデルの弱点を補うために足した指示です。
モデルを替えたら、過去の回避策が今も必要か見直します。
目的を守る条件と、昔の癖に合わせた指示を分けます。

- 根拠の段階：公式で確認
- 確認範囲：特定モデル向けの、強調や思考指示の見直しです。
- 道具を使う推論モデル：目的、必須条件、道具を使う条件を明示します。
- 軽量な文章モデル：作業順と合格例を残して、一文ずつ比較します。
- 使いどころ：モデル変更後の要約・比較表・手順説明で、指示が長い時や過剰な作業が出る時です。

これは比較を始めるための使い分け案で、性能順位ではありません。

新しいモデルなら全て短くすべき、とは言えません。

## 2. 仕組み（なぜ効くか）

弱い反応を補う指示が、反応の強いモデルでは過剰になります。
[公式ガイド](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#tool-usage)は、道具の強い利用指示を例にします。
Opus 4.5と4.6では、強い表現を弱める案を示します。
これは特定モデルの説明であり、全モデルの法則ではありません。

[Opus 5.5の公式ガイド](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#prompts-written-for-thinking-disabled)は、思考を使わない旧設定を扱います。
過去の補助指示が、今も必要かを確かめるよう求めます。
一方、既存のOpus 5向け指示は、そのままでも使えるとします。
更新日は、全削除の理由にはなりません。

効く理由は、不要な行動の誘発を減らせるためと考えられます。
何行減らせば何割良くなるかは未確認です。
安全条件や本人の目的を削る根拠にもなりません。

## 3. 使い方（手順と例）

差分は、変更前と変更後を並べた修正案です。

1. 今使うモデルと、依頼したい仕事を確認します。
2. そのモデルの公式指示ガイドを開きます。
3. 過去の失敗を補うための文を拾います。
4. 各文の目的、古い前提、現在の必要性を分けます。
5. 一箇所だけ、差分で言い換えます。
6. 同じ小さな仕事で、元の版と比べます。

見直す候補は、次のように整理します。

| 候補 | 確かめること |
| --- | --- |
| 必ず、絶対に、毎回という強調 | 本当に全ての場面で必要か。 |
| とにかく徹底的に調べる | 作業に必要な範囲を越えていないか。 |
| 常に全ての思考を本文に書く | 短い理由の説明で目的を満たせるか。 |
| 古い道具名やモデル名 | 現在の公式文書と一致するか。 |
| 定型の手順や例 | 今のモデルにも役立っているか。 |

自作の点検依頼です。

```text
この指示文を、今使うモデルに照らして見直してください。
目的と、必須の制約は維持してください。
昔の回避策らしい文を、根拠とともに挙げてください。
各文に「残す・言い換え候補・判断材料不足」を付けてください。
公式ガイドの該当節と、最小の差分案を示してください。
ファイルは変更せず、提案だけ返してください。
```

例として「毎回、必ず道具を使え」を点検します。
「現状の確認が必要な時に使う」への変更を検討できます。
ただし、道具使用が必須の仕事では元の条件を残します。

大声のような言葉や脅しに、固有の改善効果は確認できません。
必要性は、目的、理由、適用範囲で伝えます。

## 4. 試し方（最初の一歩と測り方）

以下は50分で終える検証案です。時間と閾値はこの葉で決めた目安です。

1. 準備10分：古い指示を一つ保存し、強調の一文だけを条件文に変えます。
   300字以内の資料3件を用意し、各仕事の必須条件を3個ずつ書きます。
   例は要約1件、比較表1件、手順説明1件です。
   不要な作業も先に定義します。例は、資料だけで足りる時の追加検索です。
2. 比較20分：同じモデル・設定・資料で、元の版と修正版を各3件試します。
   別の会話で計6回答を保存し、途中の追加指示はしません。
3. 採点15分：必須条件9個の抜け数と、不要な作業の合計数を人が数えます。
   各回答を使える状態にするための修正箇所数も記録します。
4. 判定5分：修正版の条件抜けが0個、不要な作業が1件以上減り、
   修正箇所数が増えなければ、この3件では改善候補とします。

差がない場合や50分で比較が終わらない場合は、必要性を未確認とします。
この小試行だけで、別モデルや全作業への効果を断定しません。
自動で変更案を探す仕組みは、05_評価と改善で扱います。
