## 1. 要点（一言と、根拠の段階と、使いどころ）

分からない事実と、相談のための仮定を分けて書かせる。

- 根拠の段階：公式で確認（不確かさの明示。三つの欄の効果は未検証）。
- 推論に時間を使えるモデルには、目的と資料を渡し、仮定と結論の関係を短く示させる。
- 速度重視の軽量モデルには、確認済み・仮定・未確認の欄と、各欄に書く内容まで渡す。
- 使いどころ：草案、設計相談、画像の読み取り、調査報告。

モデル別の使い分けは、ここで試すための案である。

仮定とは、検討を進めるために一時的に置く条件である。
未確認とは、事実だと確かめられていない状態である。
仮定を置く許可と、未確認の事実を作る許可は別である。

## 2. 仕組み（なぜ効くか）

隠れた仮定は、出力のどこを直せばよいか分かりにくい。
仮定を表に出せば、本人が短く訂正できる。
その仮定に依存する結論も、見直す場所を絞れる。
これは指示設計からの推測であり、効果量は未確認である。

Anthropic公式は、不確かなときに不明と答えてよいと明示し、
主張を資料の引用で確かめ、裏づけがなければ撤回させる方法を示す。
根拠と主張を対応させるため、人が断定を点検できる。
この仕組みを「確認済み」と「未確認」の区別に使う。
ただし、この方法でも事実誤認はなくならない。[公式の根拠確認方法](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)

保存画像には、仮定を明確にする規則が見える。
画像だけでは、その規則が品質を上げたとは言えない。
ここでは、確認可能な指示の型として取り入れる。

## 3. 使い方（手順と例）

1. 根拠に使う資料と、検討の目的を指定する。
2. 確認済みの事実と、その根拠を先に示させる。
3. 草案に必要な仮定だけ、理由付きで置かせる。
4. 仮定が違う場合に変わる結論を示させる。
5. 結論を大きく変える不足は、本人へ質問させる。

賢いモデルへの例：

```text
この画面を基に、初めて使う人向けの説明案を作ってください。
確認できた動作と、相談用に置いた仮定を分けてください。
仮定が違うと変わる説明も、一行で示してください。
実際の動作が分からない部分は、未確認として残してください。
結論を変える不足だけ、質問してください。
```

軽いモデルへの例：

```text
次の三つの欄で返してください。
確認済み：資料のどこで分かるかを添える。
仮定：草案を作るために置いた条件と、その影響を書く。
未確認：分からない動作と、確認方法を書く。
画像から読めない寸法や色は、推定と明記してください。
```

試せなかった項目は、実施済みにまとめない。
「未実施」と理由を書かせると、判断材料が残る。
存在しない操作名やコマンドを、仮定として作らせない。
事実が必要な箇所は、未確認のまま扱う。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、合計50分の比較とする。以下の数値はこの葉の検証案であり、実測結果ではない。

1. 準備10分：500字以内の架空の説明書を1件作る。操作の事実5件と、未確定の条件2件を別紙に列挙する。
2. 作成10分：同じモデル・設定・資料・300字以内の出力で、通常の指示と三つの欄付きの指示を、別の新しい会話で各1回試す。
3. 採点15分：別紙と照合し、資料にない断定数と、未確定条件を明示できた数（0～2件）を数える。
4. 訂正10分：未確定条件を1件確定させ、両方の草案を直す。変更が必要な箇所を人が先に列挙し、修正漏れを数える。
5. 判定5分：三つの欄付きが「資料にない断定0件、未確定条件の明示2/2件、修正漏れ0件」を満たせば、この題材で合格とする。

通常の指示も同じ条件を満たすなら、優位性は確認できなかったと記録する。
余分な未確認欄の件数も記録し、必要以上に回答が膨らんでいないかを見る。
この1件で、別の作業やモデルへの効果までは判定しない。

読みやすさが落ちるなら、欄を回答の末尾へまとめる。
仮定の明示だけで、事実確認を省かない。

- 公式・論文など：
  - [元記事](https://joulyan.com/en/blog/why-claude-code-sessions-hit-limits-and-how-to-keep-them-small)
  - [不確かさを明示する公式の説明](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)
- 確認の限界：
  - 記事そのものの投稿URLは未確認。
  - 仮定の抽出精度と、未確認事項の見落とし率は未確認。
  - 公開Xの現状は未確認で、投稿との対応は保存画像に依存する。
