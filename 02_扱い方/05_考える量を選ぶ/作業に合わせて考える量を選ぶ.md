## 1. 要点（一言と、根拠の段階と、使いどころ）

effort は、モデルが仕事へ割く量の目安です。
トークンは、モデルが文章を処理する小さな単位です。

**必要な品質を満たす範囲で、考える量を選びます。**

- 根拠の段階：本体と公式で確認
- 使いどころ：effortに対応するClaude OpusやSonnetで、調査、設計、実装を比べます。
- 指示の抽象度：目的は抽象的でも、合格条件は具体的にします。
- 軽いモデル：同じ設定が使えるとは限りません。

本体では設定名と選択肢を確認しました。
私の作業での最適値や節約率は未確認です。

## 2. 仕組み（なぜ効くか）

effort は、使う量を厳密に固定する設定ではありません。
思考だけでなく、説明や道具の利用にも影響します。
低い設定でも、難しい問いでは考える場合があります。
[Claude APIの公式説明](https://platform.claude.com/docs/en/build-with-claude/effort)は、
この性質を厳密なトークン予算ではなく、行動の目安として説明しています。

量を増やせば、検討する余地は増えます。
その一方で、時間や消費量も増える可能性があります。
このため、常に最大値が最適とは限りません。
[Claude Codeの公式説明](https://code.claude.com/docs/en/model-config#choose-an-effort-level)では、
高い設定で境界条件や検証を増やし、低い設定では早く出発点を返す傾向を示しています。
したがって、人がすぐ確かめる名前変更と、検証が必要な不具合調査を分けて比較します。
効果の保証ではなく、自分の課題で比較する理由です。

同じ段階名でも、モデル間で内部の量は同じではありません。
モデルを替えたら、以前の値も見直します。

学習時の計算と、回答時に使う計算は別です。
考える量の調整は、モデル自体の交換ではありません。
[追加計算の一次論文](https://arxiv.org/abs/2408.03314)の要旨では、
効果が問題の難度で変わりました。
ある程度解ける小型モデルが伸びる、条件付きの結果です。
全ての小型モデルが大型モデルを代替する根拠ではありません。

## 3. 使い方（手順と例）

1. 合格条件を先に書きます。
2. モデル名と、現在の effort 表示を確認します。
3. 既定値で試し、不足がある場合に一段上げます。
4. 簡単な作業では、一段下げた結果も比べます。
5. 条件を満たす値を、そのモデル用に記録します。

Claude Code では、`/effort` で設定を確認できます。
起動時の `--effort` は、その会話だけに適用できます。
以下は設定例であり、この調査では実行していません。

```text
claude --effort medium

この関数の不具合を直してください。
空の入力、通常の入力、上限の入力を満たすこと。
外部向けの関数名は変えないでください。
```

上限が必要なら、`maxEffortLevel` を検討します。
これは選べる段階の上限であり、請求額の上限ではありません。
設定例は `{"maxEffortLevel":"high"}` です。
組織などの制限がある場合は、その制限も適用されます。

名前の一括変更と、不具合の原因調査を分けて考えます。
前者は結果を照合しやすく、後者は複数の原因を検討します。
両方へ最大値を固定せず、必要な品質で比べます。
深い検討を求める文章と、設定値も区別します。
`ultrathink` の機能は、関連する葉にまとめています。

## 4. 試し方（最初の一歩と測り方）

以下は50分の検証案です。今回の点検では実行していません。
すでに使える対応モデル一つで、既定値と一段低い値を比べます。
下げられる値がない場合は比較不可とし、二段階を選べるモデルで行います。

1. 準備10分：正解を確認できる小さな修正を二件用意します。
   名前変更一件と、境界条件のある不具合修正一件にします。
   各入力は30行以内のコードとし、採点対象は修正案の回答だけにします。
   各課題に五つの合格項目を設け、依頼文と入力を固定します。
2. 比較20分：二件×二設定の計四回を、別々の新しい会話で試します。
   一回4分を上限にし、残り4分を会話の切替と記録に使います。
   未完了はそのまま記録し、時間内に四回答が揃わなければ採否を保留します。
   モデルの版と、画面に表示された適用設定を残します。
3. 採点15分：各回答を五項目の0/1点で採点します。
   設定ごとの合計点を10点満点にし、待ち秒数、使用量、手直し回数を並べます。
4. 判断5分：両設定10/10点で、低い設定の合計待ち時間が20%以上短ければ、
   この二件では下げる候補とします。品質が落ちれば既定値を保ちます。

件数と20%は最初の比較用の仮の基準で、一般的な節約率ではありません。
使用量が見えない場合は「未確認」とし、回答の短さで思考量を代用しません。
次回は種類の違う三件へ広げ、モデルや道具が変わったら再び比べます。
