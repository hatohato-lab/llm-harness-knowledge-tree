## 1. 要点（一言と、根拠の段階と、使いどころ）

ultrathink は、Claude Code が扱う特定の入力語です。
effort は、モデルが仕事へ割く量の目安です。
API は、プログラムからモデルなどを呼ぶ窓口です。

**一回の難問にだけ、深い検討を求める指示を足します。**

- 根拠の段階：本体と公式で確認
- 使いどころ：賢いモデルによる難しい設計判断や原因調査です。
- 指示の抽象度：目的を抽象的に伝え、制約と判断材料を添えます。
- 軽いモデル：能力不足を、この語だけで補えるとは限りません。

対象は Claude Code 上で使う、思考機能を備えた推論モデルです。
モデル名と effort を記録し、他社モデルや通常のチャットへ特別処理を一般化しません。
向く作業は、同時更新の失敗条件など、反例を資料や小さなテストで確認できる一問です。

## 2. 仕組み（なぜ効くか）

[Claude Code 公式](https://code.claude.com/docs/en/model-config#use-ultrathink-for-one-off-deep-reasoning)によれば、この語を見つけると指示を追加します。
追加するのは、会話の中で深い検討を求める指示です。
現在は、APIへ送る effort の値を変えません。
常に最大値へ切り替える、という説明は誤りです。

したがって、モデルへの依頼内容を変え、その一問の検討を深めるよう促す仕組みです。
これは公式にある処理からの説明であり、正答率が上がることの実測根拠ではありません。

`think hard` などは、特別な入力語として扱われません。
普通の指示として渡されます。
`ultra think` の空白入り表記の特別扱いは未確認です。

この語の処理と、答えの改善は別の主張です。
深い検討を促せても、正しい結論は保証されません。
どの作業で役立つかは、結果で確かめます。

## 3. 使い方（手順と例）

1. 判断に迷う問いを一つに絞ります。
2. 目的、制約、分かっている事実を書きます。
3. 依頼へ `ultrathink` を添えます。
4. 結論を左右する根拠と、確かめ方を求めます。

```text
ultrathink
この保存方式が、同時更新に耐えるか検討してください。
利用者は最大20人で、更新は一件ずつ記録します。
失敗する条件と、その確認方法を挙げてください。
結論と、判断を左右する根拠を短く示してください。
```

手順のすべてを先に固定する必要はありません。
ただし、使える資料や守る制約は省略しません。
他社のサービスでも同じ特別処理があるとは限りません。

## 4. 試し方（最初の一歩と測り方）

最初は合計50分の比較を計画します。以下の時間と合格条件は、この葉の検証案です。

1. 準備10分：過去に解決した小さな設計問題を1問選び、正しい指摘3項目と、それぞれを裏づける資料を先に用意します。
2. 比較20分：同じモデル・effort・入力資料で、入力語なし／`ultrathink` ありを別の会話で1回ずつ試します。どちらも結論・根拠・確認方法の形式にそろえます。
3. 採点15分：正しい指摘の数を0〜3点、誤った指摘と見落としの件数、所要秒数を記録します。正誤は準備した資料に照らします。
4. 判断5分：入力語ありで正しい指摘が1点以上増え、誤った指摘が増えなければ、別の問題でも試す候補とします。同点は効果未確認とします。

50分で終わらなければ、未完了の件数を残し、採用判断は見送ります。
1問2回答だけで効果を断定せず、長さや強い言い切りも改善と数えません。

効果がなければ、前提や材料の不足を調べます。
同じ語を何度も足す方法の有効性は未確認です。
