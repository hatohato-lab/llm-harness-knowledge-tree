## 1. 要点（一言と、根拠の段階と、使いどころ）

拡張思考は、回答の前などに行う追加の推論です。
適応的思考は、必要な場面と量をモデルが選ぶ方式です。
effort は、モデルが仕事へ割く量の目安です。
環境変数は、起動するプログラムへ渡す設定値です。

**古い設定を流用せず、モデルの版と表示を照合します。**

- 根拠の段階：本体と公式で確認
- 使いどころ：Opus・Sonnet の版を替えた後の設定点検や、名前変更などの小修正と、不具合の原因調査で effort を使い分ける場面です。
- 指示の抽象度：小修正では対象ファイル・変更箇所・合格条件まで具体化し、原因調査では症状・再現条件・変更禁止範囲を渡します。比較中は指示を固定します。
- 軽いモデル：Haiku などへ替える際も、同じ設定が使えると仮定せず対応表を確認します。対応外の設定を足しても、思考量は指定できません。

## 2. 仕組み（なぜ効くか）

[公式の適応的思考の説明](https://code.claude.com/docs/en/model-config#adaptive-reasoning-and-fixed-thinking-budgets)では、単純な段階の思考を省き、必要な段階に深い思考を使う仕組みが示されています。
以前は、思考に使う量を固定する方式がありました。
適応的思考では、モデルが各段階の必要量を判断します。
そのため、旧方式の設定が新方式でも効くとは限りません。
思考機能が常に有効でも、毎回同じ量を考えるわけではありません。
文書、設定値、実際の表示を合わせることが重要です。

[公式の effort の適用順序](https://code.claude.com/docs/en/model-config#adjust-effort-level)に従うと、Claude Code ではモデル別に effort を保存できます。
新しいモデルは、利用者設定直下の旧値を使わない場合があります。
これは設定ファイル全体が無効という意味ではありません。
プロジェクトや管理者の設定とは、適用条件が異なります。

設定の名前が本体にあるだけでは、全モデルへの対応は分かりません。
対応範囲は、現行の公式文書で確かめます。

## 3. 使い方（手順と例）

1. `/model` でモデルの版を確認します。
2. `/effort` と会話の表示で、現在の値を確認します。
3. `/config` で思考を切り替えられるか確認します。
4. 旧設定と環境変数の有無を、変更前に調べます。
5. 対応している指定方法に合わせ、表示で再確認します。

2026年10月4日の Claude Code 文書では、次の区別があります。

| 対象 | 扱い |
| --- | --- |
| Opus 4.6、Sonnet 4.6 | 固定思考量へ戻す設定がある |
| Opus 4.7以降、Sonnet 5以降、Fable | 常に適応的思考を使う |
| Opus 5.5、Sonnet 5.5、Fable | 思考停止の指定が効かない |

`MAX_THINKING_TOKENS=0` を万能な停止方法にしません。
対応するモデルでも、接続先で扱いが変わります。
別会社経由では、停止を保証しない場合があります。

モデル別に保存する構造の例です。
この調査では設定ファイルを変更していません。

```json
{
  "modelSettings": {
    "claude-opus-5-5": {
      "effortLevel": "medium"
    }
  }
}
```

`CLAUDE_CODE_EFFORT_LEVEL` による上書きも調べます。
希望値を書いたことと、適用されたことを分けます。

## 4. 試し方（最初の一歩と測り方）

最初は、設定を書き換えずに45分でできる対応範囲の点検を行います。
時間と合格条件は、この葉の検証案です。モデルへの依頼送信は不要です。

1. 10分：第3節の表を読み、以下の3例について「旧設定が効くか」と「使う設定」を先に紙へ書きます。手順3の期待する判定は、採点まで見ないようにします。
2. 15分：公式の該当箇所と照合します。例① Opus 4.6で固定予算へ戻す指定、例② Opus 5.5で `MAX_THINKING_TOKENS=0`、例③ Opus 5.5で利用者設定直下にだけ `effortLevel` がある場合です。
3. 10分：各例の判定・使う設定・根拠リンクがすべて正しければ1点、合計3/3点を合格にします。期待する判定は① `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1` で固定予算へ戻し `MAX_THINKING_TOKENS` で量を指定できる、②停止不可なので `/effort` で量を選ぶ、③利用者設定直下の旧値は適用されず `modelSettings` 内のモデル別設定を確認する、です。他の上書き設定はない例として比べます。
4. 10分：利用中の画面や既存記録があれば、モデル名・effort表示・思考停止可否の3項目を転記し、どの例に近いか照合します。見られない項目は未確認と書きます。

3/3点は設定の読み分けの合格で、速度や品質の改善を示す値ではありません。
実運用の比較を後で行うなら、同じ小修正3件について設定変更前後の合格件数・所要秒数・使用量を記録します。
停止不可のモデルでは effort だけを変え、モデルと指示文は固定します。設定の理解と実運用の効果を分けて記録します。
