## 1. 要点（一言と、根拠の段階と、使いどころ）

使う言語と文体を指定し、短い見本で好みを伝えます。

- 根拠の段階：言語指定と見本利用は公式で確認。日本語での改善幅は未検証。
- 指示追従に対応した推論型モデルには、回答言語と文体の方針、見本を渡します。
- 軽量な汎用モデルには、語尾、用語、残す数字を項目ごとに指定します。
- 使いどころ：英語資料の日本語説明や、自分の文体での推敲に向きます。

以上の使い分けは検証する運用案で、モデル間の比較結果ではありません。
設定項目の `language` はClaude Code向けです。
ほかの対話モデルでは、回答言語を依頼文に書いて試します。

文体は、語尾、言葉の選び方、文章の調子です。
ここでいう見本は、まねてほしい表現の例です。
見本の事実や経験を、本文に移す指示ではありません。

## 2. 仕組み（なぜ効くか）

「自然に書く」だけでは、自然さの意味が定まりません。
[公式の見本の使い方](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#use-examples-effectively)は、
例が出力の形式・調子・構造をそろえる手掛かりになると説明しています。
見本は「自然」の意味を、語尾や言葉選びの具体例に置き換えます。
このため、モデルに好みを推測させる範囲を減らせると考えられます。
最後の因果説明は、公式の指針をこの用途に当てはめた解釈です。
日本語での改善幅は、作業ごとの確認が必要です。

[公式の回答言語の指定](https://platform.claude.com/docs/en/build-with-claude/multilingual-support#set-the-response-language)は、
会話からの推測に任せず、目標の言語を明示する方法を案内しています。
入力資料の言語と、回答の言語は別に指定できます。
文体を直す場合も、事実を残す条件を分けて書きます。
表現が滑らかでも、内容が正しいとは限りません。

保存投稿には、日本語の指定後に英語化した反例があります。
設定や指示の存在は、完全な遵守を保証しません。
同じ指示を二重に書く効果も、一般化はできません。

返答の言語設定と、常設指示の文体もそろえます。
設定の未読込と、読込み後の不遵守を分けて調べます。
返答の言語は、画面の表示言語を変える機能とは別です。

## 3. 使い方（手順と例）

1. 入力資料と回答の言語を指定します。
2. ですます調など、必要な語尾を決めます。
3. 自分が読んで納得できる見本を添えます。
4. 原文から変えてはいけない情報を示します。
5. 表現と事実を、別々に確認します。

```text
英語資料を、日本語のですます調で説明してください。
製品名とコードの名前は、原文の表記を保ってください。
専門用語には、初出で短い説明を添えてください。
文体は、次の見本の語尾と語彙を参考にしてください。
見本にある事実や体験は、対象文へ足さないでください。
見本：＜自分の文章2段落＞
対象文：＜今回の原稿＞
```

推敲では、数字、引用、固有名詞、出典を保持させます。
情報を補った場合は、その部分を分けて示させます。
英語用の表現規則を、日本語へそのまま移しません。

毎回同じ言語を使う場合は、設定との整合も確かめます。
`language` は、Claude Codeの返答言語の設定です。
`settings.json` は、動作を指定する設定書です。

1. 適用される設定に `language` があるか確認します。
2. 同じ項目を上書きする設定も確認します。
3. 必要な場合だけ、既存設定へ言語の項目を加えます。
4. 常設指示に、語尾と原語を保つ条件を書きます。
5. 新しい会話で、英語資料の説明を試します。

JSONは、設定名と値を組にする書式です。
次は一項目の例です。既存設定全体と置き換えません。

```json
{ "language": "japanese" }
```

常設指示の例は「返信は日本語のですます調にする」です。
「技術用語とコードの名前は原語を保つ」も添えられます。
設定の保存場所と優先順位は、文脈と記憶の枝で扱います。

## 4. 試し方（最初の一歩と測り方）

次は今後実施する45分の検証案です。時間と閾値は、この葉で決めたものです。
最初は設定を変えず、短い原稿で見本の有無だけを比べます。

1. 準備10分：公開できる原稿1段落と、自分の文体の見本2段落を選びます。
   回答は3文に固定し、残す数字・固有名詞・事実を先に一覧にします。
2. 比較15分：同じモデル・原稿・言語指定で、独立した会話を4件用意します。
   見本なしと見本ありを各2回試し、回答を保存します。
3. 採点15分：各回答の日本語3文と、ですます調の語尾3個を採点します。
   3文でなければ文数不一致として未達にします。
   自分で直したい表現、事実の追加・脱落、数字・固有名詞の変更も数えます。
4. 判定5分：見本ありの2回答で言語・語尾が計12項目すべて合い、
   事実の追加・脱落と保護した情報の変更が0件なら採用候補です。
   表現の修正数の合計が見本なしより1件以上少ない場合だけ改善ありとします。

両条件の修正数が0件なら、差は検出できていません。
設定変更や長い会話の後半での日本語維持は、別の試行で調べます。
設定値の存在は成功と数えず、実際の回答で判定します。
今回は原稿の送信、回答の生成、設定変更を実施していません。
