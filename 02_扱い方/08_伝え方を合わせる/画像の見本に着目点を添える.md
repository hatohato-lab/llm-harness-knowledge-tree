## 1. 要点（一言と、根拠の段階と、使いどころ）

見本の画像に、見る場所と採用したい特徴を添えます。

- 根拠の段階：画像利用は公式で確認。着目点による改善幅は未検証。
- 画像入力対応の推論型モデルには、画像と目標、採用する特徴を渡します。
- 画像入力対応の軽量な汎用モデルには、色、配置、文字を一項目ずつ指定します。
- 画像を読めないテキスト専用モデルは、この手順の対象外です。
- 使いどころ：画面の設計、見た目の修正、操作画面の質問。

モデルごとの指示の細かさは、この葉で試す運用案です。
モデル間の優劣を測った結果ではありません。

画像入力は、画像の内容をモデルに読ませる機能です。
使うモデルと接続先が、この機能に対応する必要があります。
画像を見せただけで、好みまで確定するわけではありません。

## 2. 仕組み（なぜ効くか）

配置や余白は、言葉だけでは伝えにくいことがあります。
[公式の画像利用手順](https://code.claude.com/docs/en/common-workflows#work-with-images)は、
文章で説明しにくい見た目を、画像で渡す方法を案内します。
[公式の明確な指示の説明](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#be-clear-and-direct)は、
期待する出力と制約を具体的に示すよう勧めています。
画像は配置の情報を補い、着目点は比較する項目を指定します。
この二つを合わせれば、好みを推測させる範囲を狭められます。
後半は公式の二つの指針を組み合わせた、この葉の解釈です。
手戻りの減少や改善幅は、まだ比較して確かめていません。

画像から読めた事実と、推定した値を分けます。
[公式の画像読解の限界](https://platform.claude.com/docs/en/build-with-claude/vision#limitations)では、
低品質な画像の誤読や、位置の推定が概算になる点を挙げています。
字体や寸法を、見ただけで確定した扱いにしません。

参考画像、現在の画像、目標の画像には名前を付けます。
「画像Aの余白を採用」と書けば、対応関係が分かります。
画面の質問では、直前の操作と疑問も添えます。
画像だけで、不具合の原因が断定できるとは限りません。

## 3. 使い方（手順と例）

1. 必要な部分が読める画像を用意します。
2. 各画像が見本か現状かを明記します。
3. 比べる点を、少数の項目に絞ります。
4. 観察と推定を分けて説明させます。
5. 採用する特徴を、言葉で確定します。

```text
画像Aは参考、画像Bは現在の画面です。
文字の大きさ、余白、情報の並び方を比べてください。
参考にするのは、画像Aの広い余白と見出しの配置です。
色と文章の内容は、画像Bのままにしてください。
画像から確定できない寸法や字体は、推定と書いてください。
まず差と修正案を説明してください。
```

操作画面を質問する場合の例です。

```text
この画像は、保存ボタンを押した直後の画面です。
目標は、文書を現在のフォルダへ保存することです。
赤枠の表示の意味と、次に確認する項目を教えてください。
画面だけで分からない点は、分からないと書いてください。
```

画像を作る道具と、画像を読む能力は別です。
道具の導入や画面操作の実行は、04_工程で扱います。

## 4. 試し方（最初の一歩と測り方）

次は今後実施する40分の検証案です。時間と閾値は、この葉で決めたものです。
見本1枚の特徴説明を比べ、実装や画像生成は頼みません。

1. 準備10分：共有できる画像1枚を選び、採用したい特徴を3個書きます。
   画像で読める文字と、確定できない寸法も正解表に記します。
2. 比較15分：同じ画像・モデル・回答量で、独立した会話を4件用意します。
   「特徴を説明」だけの条件と、着目点3個を添える条件を各2回試します。
3. 採点10分：各回答で、意図した特徴の一致数を0〜3個で記録します。
   誤読した文字数と、根拠のない寸法の断定数も数えます。
4. 判定5分：着目点ありの2回答とも3個一致し、誤読・断定が0件なら採用候補です。
   一致数の合計が、着目点なしより1個以上増えた場合だけ改善ありとします。

両条件が最初から満点なら、この試行では改善を検出できていません。
別画像・別モデルへの効果は、この4回答から一般化しません。
今回は画像を外部へ送らず、回答の生成も実施していません。

  - [画像読解の限界](https://platform.claude.com/docs/en/build-with-claude/vision#limitations)
- 確認の限界：
  - 別の外部記事は必要ありません。
  - 投稿の画像そのものや、比較結果の再現は未確認です。
  - 外部の設計手順が必須だという根拠はありません。
  - 形式の受け入れは、見た目の改善を保証しません。
  - 着目点を添える手法そのものは依頼文なので、専用の実装はありません。
  - ほかにも、確認できていない点が複数あります。
