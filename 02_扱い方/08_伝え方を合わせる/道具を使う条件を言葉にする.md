## 1. 要点（一言と、根拠の段階と、使いどころ）

使う道具の名前だけでなく、使う場面も指定します。

- 根拠の段階：公式で確認
- 道具を呼べる推論モデルには、必要な情報と判断条件を短く渡します。
- 道具を呼べる軽量モデルには、使う例と似ている対象外の例を各2件添えます。
- 使いどころ：資料の検索、事実の確認、計算、既存文書の参照。

道具を呼べない文章生成だけのモデルでは、呼出結果の評価はできません。
上の例数は、この葉で比較するための指示案です。

ツールは、モデルが呼び出す検索や計算などの道具です。
スキルは、必要な場面で読む再利用用の手順書です。
道具が使えることと、適切に選ぶことは別です。

## 2. 仕組み（なぜ効くか）

「必要なら検索」では、必要の意味を推測させます。
「最新の仕様を尋ねられたら公式を検索」と書けます。
条件を言葉にすると、選択の基準が明確になります。
これは道具の選択についての説明です。
どの表現が最良かは、作業ごとの試行が必要です。

[公式の道具定義](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools#best-practices-for-tool-definitions)では、
用途・非用途・入力・制約を説明すると、選択と使い方を判断する文脈が増えるとしています。
したがって、条件を明記する狙いは「必要」の推測を減らすことです。
改善する割合は、この葉ではまだ測っていません。
[公式の道具使用の説明](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#tool-usage)では、
Claude Opus 4.5と4.6は強すぎる強調で過剰に呼び出す場合があるとしています。
「必ず全部使う」という指定は、必要性を判断できません。

依頼の「説明」と「実行」も分けて書きます。
使い方の説明だけを求めるのか、実行を求めるのかを示します。
言葉による条件指定は、権限の制御を代替しません。

## 3. 使い方（手順と例）

1. 解決に必要な情報を決めます。
2. その情報を得られる道具を指定します。
3. 使う条件と、使わない条件を書きます。
4. 道具が返せない情報も示します。
5. 説明だけか、実行までかを明記します。

```text
最新版の仕様が答えに必要なら、公式文書を検索してください。
渡した資料だけで答えられる要約は、その資料を使います。
検索した場合は、開いたページと確認日を示してください。
取得できない情報は、未確認と書いてください。
今回は調査と説明までです。
```

似た依頼を二つ並べると、条件の境界を伝えられます。

| 依頼 | 道具を使う条件 |
| --- | --- |
| この文書に書かれた仕様を要約して | 指定文書を読む |
| 現在の公式仕様へ更新されているか調べて | 現在の公式文書を開く |
| 検索機能とは何か説明して | 検索の実行自体は求めない |

登録済みの手順書を選ぶ場合も、対象の作業を説明します。
特定の名前を毎回強制する前に、用途の説明を確認します。
[元記事のdescriptionの例](https://www.freecodecamp.org/news/how-to-build-your-own-claude-code-skill/)は、
スキルがすること、使う場面、呼び方の例を組にしています。
道具そのものの用途・非用途は第2節の公式定義で確かめます。
道具の実装や接続の設定は、04_工程で扱います。

## 4. 試し方（最初の一歩と測り方）

最初の試行は、接続済みの読み取り専用の道具1個で行う45分の計画です。
新規導入が必要なら、先に接続を終えてからこの試行を始めます。

1. 10分で使う依頼2件、似ているが使わない依頼2件を作ります。
   各件に呼出の正解と、回答が満たすべき事実1個を先に書きます。
2. 20分で4件を、名前だけの指示と条件付きの指示で各1回試します。
   合計8回です。モデル・道具・入力は同じにし、会話は毎回分けます。
   「使わない例」は、入力欄に全文を貼った資料の要約と道具の概念説明にできます。
   ファイルを読む道具が必要な依頼を、対象外の正解には混ぜません。
3. 10分で呼出履歴を読み、未呼出数・不要な呼出数・回答の正解数を数えます。
   呼ぶべき2件の呼出率、対象外2件の誤呼出率を別々に計算します。
4. 5分で2条件を比べ、どの条件の言葉が曖昧だったかを1行で残します。

この試行の合格条件は、条件付き指示で必要な呼出2/2件、
不要な呼出0/2件、回答の正解4/4件を満たし、基準版より悪化しないことです。
両方が全問正解なら「改善は未確認」と書きます。
45分と件数・閾値はこの葉の仮の基準で、一般的な性能保証ではありません。
時間切れは未達です。今回は実際の道具呼出を伴う比較をしていません。
