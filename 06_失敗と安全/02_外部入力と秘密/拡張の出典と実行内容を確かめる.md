## 1. 要点（一言と、根拠の段階と、使いどころ）

拡張は、入れる前に実行内容と通信先を読みます。
根拠の段階は「公式で確認」です。
本体と、この環境での実行結果は未確認です。

プラグインは、手順や接続先をまとめた追加機能です。
スキルは、必要な作業で読む再利用用の手順書です。
フックは、決めた出来事で処理を動かす機能です。
MCPは、AIと外部の道具をつなぐ通信規格です。
Modsは、本体の処理や表示を変える拡張です。

賢いモデルは、処理のつながりや隠れた送信の点検に向きます。
軽いモデルは、確認項目の列挙と差分の抽出に向きます。
指示は、読むファイルと禁止操作を具体的に書きます。
外部スキル、MCP、フックの導入と更新で使います。

## 2. 仕組み（なぜ効くか）

拡張には、AIへの指示と実際に動く処理が混在します。
公式は、フックやサーバーが利用者の権限で動くと説明します。
AIの道具に対する制限だけでは、拡張自身を囲えません。
そのため、導入は実行を任せる判断として扱います。
[公式の安全説明](https://code.claude.com/docs/en/plugins/security)

Modsは、秘密を読み、道具の承認にも介入できます。
安全対策を加える拡張自身の権限も、点検が必要です。
[Modsが届く範囲](https://code.claude.com/docs/en/plugins/mods/overview#what-a-mod-can-reach)

配布元の名前だけでは、個々の実行内容は分かりません。
部品の一覧から、その部品が呼ぶ処理まで追います。
秘密を読む処理や、外へ送る処理を導入前に見つけます。

検査用の道具にも、独自の通信があります。
SkillSpectorは、拡張の危険を調べる検査用の道具です。
OSVは、既知の弱点を調べる公開データベースです。
SkillSpectorは、既定でAI解析が有効です。
対象本文を設定したAI提供元へ渡すため、送信先の確認が必要です。
AI解析を止めても、依存名と版をOSVへ照会します。
検査合格は、導入後の隔離や安全を保証しません。
[検査道具の送信と限界](https://github.com/NVIDIA/SkillSpector#trust-model-and-data-egress)

## 3. 使い方（手順と例）

1. 現在の道具では不足する用途を一つ書きます。
2. 配布元、作者、版、利用許諾を記録します。
3. 手順書と同梱処理を、実行せずに読みます。
4. 起動処理、追加導入、通信先、秘密の読取りを列挙します。
5. Web取得先と、使用するAI提供元の条件を照合します。
6. 許可範囲と必要性が説明できない部品は保留します。

確認先の例は、手順書、フック設定、MCP設定です。
実行ファイルの置場と、そこから呼ぶ処理も読みます。
導入後に初めて検査する順序は避けます。
認証や初回起動の処理も、確認対象に含めます。

依頼例です。

```text
指定した拡張の配布元と同梱ファイルだけを読んでください。
導入、実行、認証、送信は行わないでください。
実行時点、権限、通信先、秘密の読取りを表にしてください。
根拠のファイル名を示し、不明な処理は未確認と書いてください。
```

## 4. 試し方（最初の一歩と測り方）

最初は50分で、導入候補一つの説明書と処理を読む机上点検です。
数値目標はこの葉の試験案で、提供元の実測値ではありません。

1. 10分で用途を一つ決め、同梱ファイルが5個以内、合計300行以内の候補を選びます。
2. 25分で全ファイルを読み、下の5項目に根拠のファイル名と行を付けます。
3. 10分で人が同じ箇所を読み、表の説明が根拠と一致するか採点します。
4. 5分で一致数、未確認数、導入を保留する理由を記録します。

| 点検項目 | 表に書く内容 |
| --- | --- |
| 出典 | 作者、版、配布元、利用許諾 |
| 起動処理 | いつ何が動き、どの処理を呼ぶか |
| 権限 | 読取り、書込み、追加実行の対象 |
| 通信先 | 接続先と送る情報、または通信しない根拠 |
| 秘密 | 認証情報を読む箇所、または読まない根拠 |

合格は、根拠と一致する説明が5項目中5項目、未確認が0項目です。
読めない部品や外部へ続く不明な呼出先は未確認と数え、導入を保留します。
50分で読み切れない場合も保留と記録すれば、その回の判定は終えられます。
この合格は点検表の完成を意味し、実行時の安全保証ではありません。
点検中は候補も検査道具も実行せず、本番の秘密や外部送信を使いません。
本調査では、拡張の導入も検査道具の実行もしていません。
