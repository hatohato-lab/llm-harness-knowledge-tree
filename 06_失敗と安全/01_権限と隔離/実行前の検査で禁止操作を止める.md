## 1. 要点（一言と、根拠の段階と、使いどころ）

禁止操作は、モデルの注意だけに任せず実行前に検査します。

フックとは、決めた時点に処理を呼ぶ仕組みです。
PreToolUseとは、道具を実行する直前のフックです。
denyとは、道具の呼出しを拒否する判定です。
終了コードとは、処理結果を呼出し元へ返す数字です。

- 根拠の段階：公式で確認。
- 賢いモデルでも軽いモデルでも使います。
- 指示は具体的にし、禁止対象を機械判定へ移します。
- 削除、範囲外の書込み、許可のない外部操作に向きます。
- 機能の仕様を確認しましたが、本体の実行は未確認です。
- 見逃しを完全になくす効果は未確認です。

## 2. 仕組み（なぜ効くか）

実行前の判定は、操作が起きる直前に入力を調べます。
拒否できれば、禁止事項を忘れた後でも被害を抑えられます。
実行後の記録だけでは、既に起きた操作を防げません。

公式は、PreToolUseでdenyを返す方法を示しています。
終了コード2でも、その道具の呼出しを止められます。
終了コード1だけでは、拒否を保証しません。
ただし、有効な判定データがあれば別の扱いになります。
[公式の終了コード](https://code.claude.com/docs/en/hooks#exit-code-output)

検査の登録、呼出し、拒否の成立は別々に確かめます。
設定が存在しても、対象条件が違えば呼ばれません。
単純な文字列検査では、別の操作経路が抜けます。
この限界を含めて、権限制限と組み合わせます。

## 3. 使い方（手順と例）

1. 禁止事項を、対象と操作の組合せで書きます。
2. 使われる道具と、入力の形式を調べます。
3. 実行前の検査に、短い拒否理由を返させます。
4. 通常の許可判定へ戻す場合も定義します。
5. 解析失敗や故障の時に、どう止めるか決めます。
6. 模擬入力を使い、登録と拒否の結果を分けて点検します。

以下は、判定表の例です。
危険な命令そのものは実行しません。

| 模擬入力 | 期待する判定 |
| --- | --- |
| 許可された資料の参照 | 通常の権限判定へ戻す |
| 禁止された場所への書込み | 拒否する |
| 対象が判別できない変更 | 拒否して理由を返す |
| 入力の形式が壊れている | 判定処理で拒否する |

Windowsでは、使用する道具名とパス表記も確認します。
PowerShellとは、Windowsで使う命令実行環境です。
Bashとは、別系統の命令実行環境です。
一方だけの登録で、両方を検査できるとは考えません。
[作者のWindows向け点検例](https://github.com/Suyann/claude-code-windows-hooks)

検査の時間切れが、常に拒否になるとは限りません。
背景で動く検査だけでも、実行前の停止は保証できません。
呼出し元の失敗時動作まで確認します。
[公式の時間切れ](https://code.claude.com/docs/en/hooks#timeouts)

Modsとは、本体の処理に介入できる拡張機能です。
Modsで止める案も、この型の実装違いとして扱います。
通常のフックと、判定の順序や故障時の動作は別です。
管理設定以外の拒否が、Modsで変わる場合もあります。
[公式のModsの処理](https://code.claude.com/docs/en/plugins/mods/events)

Jevとは、選択や確率を返す外部の判定モデルです。
高い確率だけを、危険操作の無条件な許可へ変えません。
固定のしきい値に弱い課題が、論文の要旨にあります。
削除や送信の安全性を証明した論文とは扱いません。
[Jevの評価論文](https://arxiv.org/abs/2609.37647)

## 4. 試し方（最初の一歩と測り方）

最初の45分は、紙かローカルの表で判定規則を試します。
導入、設定変更、道具の実行、外部送信は行いません。
この件数と合格値は、この葉の試験案であり提供元の実測ではありません。

1. 10分で、止める入力10件と通す入力10件を作ります。
   止める側には範囲外の書込み、判別不能、空の入力を入れます。
   通す側には許可範囲の参照を入れ、表記の違いも混ぜます。
2. 10分で、各入力の正解と理由を決め、正解欄を隠します。
3. 15分で、3節の判定規則だけを読み、20件を分類します。
4. 10分で正解と照合し、誤りのあった規則を一つ直します。

| 指標 | 分母 | 最初の合格値 |
| --- | --- | --- |
| 禁止入力を通した見逃し | 止める10件 | 0/10件 |
| 許可入力を止めた誤拒否 | 通す10件 | 0/10件 |
| 判定理由の記入漏れ | 全20件 | 0/20件 |
| 準備から採点までの時間 | 1回 | 45分以内 |

この合格は判定表の整合性だけを示し、フックの稼働を示しません。
後日の許可された試験では、無害な模擬道具で拒否を確かめます。
登録、判定処理、本体経由の三段で結果を分けて残します。
版や設定を変えた後も、同じ20件を使って差を確認します。
