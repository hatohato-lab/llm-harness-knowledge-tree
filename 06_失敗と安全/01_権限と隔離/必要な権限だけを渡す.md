## 1. 要点（一言と、根拠の段階と、使いどころ）

読める場所と変更できる場所を、作業に必要な範囲へ絞ります。

最小権限とは、必要な操作だけを許す設計です。
MCPとは、AIと外部の道具をつなぐ通信規格です。
読取り専用とは、参照できても変更できない権限です。

- 根拠の段階：公式で確認。
- 賢いモデルでも軽いモデルでも使います。
- 指示は具体的にし、場所と操作の組合せを書きます。
- 調査、資料整理、外部資料の参照、担当分担に向きます。
- 本体の実行試験と、現在の設定の実効状態は未確認です。

## 2. 仕組み（なぜ効くか）

モデルが誤判断しても、権限がなければ変更を抑えられます。
禁止事項を思い出す負担も、モデルだけに集中しません。
ただし、権限の制限が働く操作経路に限られます。

指示文は意図を伝えますが、権限の代わりにはなりません。
公式は、指示と製品による権限判定を区別しています。
設定には、拒否、確認、許可の三種類があります。
[公式の権限仕様](https://code.claude.com/docs/en/permissions#manage-permissions)

接続先にも権限があるため、AI側だけの制限では不足します。
公式のデータベース接続例は、読取り専用の利用者を使います。
この形なら、誤った更新要求も接続先で拒否できます。
[公式の読取り専用接続例](https://code.claude.com/docs/en/mcp#example-query-your-postgresql-database)

別担当へ渡す道具も、明示して絞ります。
専任担当の`tools`を省くと、利用可能な道具を継承します。
編集道具だけ外しても、命令の実行経路が残り得ます。
[公式の担当別の道具設定](https://code.claude.com/docs/en/sub-agents#frontmatter-reference)

SDKとは、プログラムから機能を使う開発用の部品です。
SDKの`allowed_tools`は、自動承認する道具の指定です。
それだけで、使える道具全体を限定できるとは扱いません。
道具を限定する`tools`と、拒否の設定を分けて確認します。
[公式のSDK設定](https://code.claude.com/docs/en/agent-sdk/python#claudeagentoptions)

## 3. 使い方（手順と例）

1. 必要な資料と、成果物を置く場所を列挙します。
2. 読む、書く、送る、実行する権限を分けます。
3. 担当ごとに、必要な道具と場所だけを渡します。
4. 接続先でも、変更を許さない権限を選びます。
5. 一度だけの許可と、保存する許可を区別します。
6. 作業終了後に、不要な恒常的許可がないか点検します。

以下は、今回の知識の木に当てはめた設計例です。
設定を変更する手順ではありません。

| 操作 | 範囲の例 |
| --- | --- |
| 読む | 指定された調査資料 |
| 書く | 担当する枝の中だけ |
| 外部へ送る | 許可しない |
| 削除する | 許可しない |
| 他の担当へ渡す | 必要な資料名と要点だけ |

Claude Codeでは、`/permissions`で規則の出所を確認できます。
保存された許可は、次の会話にも影響する場合があります。
確認が多いという理由だけで、許可範囲を広げません。
[公式の許可管理](https://code.claude.com/docs/en/permissions#permission-system)

取引道具にも、参照と変更の分離を当てはめられます。
ただし、指示文に上限を書くだけの安全性は未確認です。
個別サービスへの接続や、実資金での試験は行いません。

## 4. 試し方（最初の一歩と測り方）

最初の30分は、権限を変えずに架空の操作表で試します。
以下の件数と合格値は、この葉の試験案であり提供元の実測ではありません。

1. 10分で、必要な操作6件と範囲外の操作6件を書きます。
   必要側は指定資料の参照3件、指定成果物への追記3件です。
   範囲外側は別の枝への追記、外部送信、削除を各2件にします。
2. 10分で、3節の権限表を使い、12件の許可・拒否を判定します。
3. 10分で、事前に決めた正解と照合し、過剰な許可を直します。

| 指標 | 分母 | 最初の合格値 |
| --- | --- | --- |
| 範囲外を許可した件数 | 範囲外6件 | 0/6件 |
| 必要な操作を誤って拒否した件数 | 必要6件 | 0/6件 |
| 権限表から判断できなかった件数 | 全12件 | 0/12件 |
| 準備から採点までの時間 | 1回 | 30分以内 |

操作は表の中で判定するだけで、ファイルや接続設定は変えません。
必要な6件がすべて通ることも確認し、禁止だけ増やす設計を避けます。
この合格は権限設計の整合性です。実際の制限の有効性は別です。
後日の許可された模擬環境では、許可と拒否の実結果を同じ表へ記録します。
