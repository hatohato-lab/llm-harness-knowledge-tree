## 1. 要点（一言と、根拠の段階と、使いどころ）

**候補と採用済みを分け、権限のある担当だけが共有先へ移します。**

昇格とは、一時的な教訓を恒常的な規則へ採用することです。
共有規則とは、次の作業や別の担当も読む指示のことです。

- 根拠の段階：**元の出典で確認**
- 確認範囲：公開実装の説明に、提案と採用の分離があります。
- 対策の位置づけ：採否の状態管理は、本資料の設計案です。
- モデル：軽いモデルは整理、賢いモデルは矛盾の点検に向きます。
- 指示：保存先、採用条件、採用担当を具体的に指定します。
- 作業：失敗記録、共有手順、規則候補の整理に向きます。

利用回数が多くても、その教訓が正しいとは限りません。
モデル別の役割分担による効果は未確認です。

## 2. 仕組み（なぜ効くか）

一度の訂正には、その時だけの条件が混じることがあります。
そのまま共有すると、別の仕事にも同じ制限が広がります。
元の発言から離れた推測も、長く残る規則になり得ます。

候補と採用済みを分けると、仮説が指示として働くのを防げます。
提案する権限と、共有先に書く権限も分けて考えます。
別のAIを置くだけでは、書込権限の分離にはなりません。

autoharnessは、作業から手順を作る公開の仕組みです。
作者資料では、振り返り役が変更案だけを出します。
別の書込役が検査し、通ったものを保存すると説明します。
これは作者の設計説明であり、導入後の効果測定ではありません。
[autoharnessの設計説明](https://github.com/tigerless-labs/autoharness#how-it-works)。

pskoettの公開手順にも、反復する教訓の採用条件があります。
3回以上、2件以上の別の作業、30日以内という条件です。
この値は作者の運用値で、最適値の実証は未確認です。
[教訓採用手順のPromotion Rule](https://github.com/pskoett/pskoett-ai-skills/blob/main/skills/self-improvement/SKILL.md#promotion-rule-system-prompt-feedback)。

## 3. 使い方（手順と例）

次は、共有規則の汚染を防ぐための追加設計です。
汚染とは、誤りや無関係な指示が知識に混ざることです。

1. 候補に識別番号を付け、通常の指示とは別の場所へ置きます。
2. 状態を「候補」とし、採用済みの一覧には含めません。
3. 共有先、適用範囲、採用を決める担当を記します。
4. 根拠の点検結果と、比較試験の結果を添付します。
5. 採用担当が、変更内容と自分の権限の範囲を照合します。
6. 通った案だけを反映し、状態を「採用済み」に変えます。
7. 保留案も、理由と元の候補を結び付けて残します。

| 候補の項目 | 架空の記入例 |
|---|---|
| 識別番号と状態 | 候補01、根拠確認待ち |
| 共有する範囲 | 表を含む報告書の作成担当 |
| 変更候補 | 出力後に表題を照合する |
| 採用する担当 | 報告手順の更新権限を持つ担当 |
| 採用判断の根拠 | 比較結果と、既存規則の点検記録 |
| 復元の参照先 | 採用前の版と変更理由の記録 |

根拠の正しさや反証の調べ方は、関連する葉で扱います。
ここでは、その点検を通る前に共有されないことを管理します。

一つの改善案に、記憶の利用範囲の拡大を混ぜません。
本人の好みや禁止事項を変える判断は、別に扱います。
事前に許可された範囲なら、毎回の確認は不要です。
権限がない共有先へは、比較に合格しても書き込みません。

依頼文の例です。

```text
この失敗を、根拠付きの規則候補にまとめてください。
保存先、採用する担当、採用判断の根拠を示してください。
採用済みの一覧へは移さず、状態を「候補」にしてください。
```

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、30分で架空の候補3件を採点する机上試験です。
紙か試験用メモで行い、有料の呼出しや設定変更は不要です。
以下の件数と合格値は、この葉の試験案です。
提供元の実測値や、研究で確立した件数ではありません。

1. 10分で、次の3候補に識別番号と架空の根拠を付けます。
2. 各候補に、共有先と採用前の版の番号も記録します。
3. 10分で、採否の状態と理由を試験用メモに書きます。
4. 残り10分で、正解表と記録の参照先を照合します。

| 候補 | 条件 | 正しい状態 |
|---|---|---|
| 候補01 | 根拠の照合が済んでいない | 保留 |
| 候補02 | 根拠は十分だが共有先の更新権限がない | 保留 |
| 候補03 | 根拠・比較結果・更新権限がそろっている | 採用済み |

「採用済み」は試験用メモ上の状態だけです。
合格は、正しい状態3/3件、条件不足の誤昇格0/2件です。
正常な候補の採用は1/1件とし、全件保留で合格にしません。
元の候補、根拠、採用前の版へ戻れる記録も3/3件を求めます。
誤りは候補番号と理由を残し、採用条件を直して再試験します。
実際の共有規則や自動記憶は、この試験では変更しません。
実装の書込制限や運用効果は、この机上試験では検証できません。
