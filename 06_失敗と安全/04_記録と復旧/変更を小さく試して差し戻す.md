## 1. 要点（一言と、根拠の段階と、使いどころ）

変更を一部で確かめ、悪化時に旧版へ戻せるようにします。
差し戻しは、変更を退けて以前の状態へ戻すことです。

- 根拠の段階：公式で確認。
- 公式は、少数の対象から試す手順を示します。
- 本体での確認：未確認。
- 推論が得意なモデルには、変更の単位と悪化条件を提案させます。
- 軽量モデルには、対象2件、変えてよい表題、守る本文、合格条件を具体的に渡します。
- 大量変換、共通指示、繰り返す手順の更新に向きます。

## 2. 仕組み（なぜ効くか）

一括変更が失敗すると、影響範囲も一度に広がります。
一部から始めると、失敗の影響を限定できます。
旧版と比較できれば、悪化した変更を退けやすくなります。

公式の一括作業例は、最初の数件で依頼を調整します。
その後に、対象全体へ広げる手順です。
[少数から試す公式例](https://code.claude.com/docs/en/best-practices#fan-out-across-files)

長期作業の公式事例も、一機能ずつの作業を重視します。
変更履歴と進捗を残し、動く状態へ戻せるようにしています。
実証の中心は、Webアプリの開発です。
一般事務への転用と効果の大きさは、未確認です。
[公式の事例](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

小さくする目的は、最少の行数を競うことではありません。
合否を確かめ、元に戻せる単位に分けることです。
必要な修正を省けば、小さくても不完全な変更になります。

## 3. 使い方（手順と例）

1. 変更前の成果と手順を、旧版として残します。
2. 今回変える一点と、対象の一部を決めます。
3. 必ず守る条件と、悪化とみなす条件を書きます。
4. 同じ入力で旧版と変更案を比べます。
5. 未確認や悪化があれば、適用範囲を広げません。
6. 復旧の影響を確認し、旧版の維持か差し戻しを選びます。
7. 合格後も、次の小さい範囲で確認を続けます。

予行は、実際に変更せず、変更予定を確認する手順です。
最初は予行で、対象と変更予定の一覧を出します。
実際に変更する段階へ進めるかは、別に判断します。
道具に予行機能があるかは、実装ごとに確かめます。

例として、文書20件の表題を直す作業を考えます。
先に複製した2件で、書き換え案だけを比較します。
本文まで変わったら、残り18件へは広げません。
「2件」は説明用であり、安全を保証する数ではありません。

```text
表題の修正案を、複製した2件だけで作ってください。
変更前の版と比べ、本文が変わっていないか確かめてください。
不一致があれば適用を広げず、原因と旧版の場所を報告してください。
採用条件、悪化条件、戻す範囲を先に書いてください。
```

外部送信など、取り消せない操作は別に扱います。
まず架空の状態で、判断と停止の分岐を確かめます。
これは紙上試行であり、実際の操作は行いません。
例えば、送信先が不明なら停止する流れを追います。
紙上試行だけで、実環境の安全性は証明できません。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、40分の紙上試行です。
文書20件の表題変更を想定し、先行対象を2件に限定します。
実データの変更や、モデルへの新たな依頼は不要です。
最初の10分で、架空の旧版2件と表題だけ直した案を紙に書きます。
本文は各2行とし、旧版の保存場所も架空の名前で付けます。
次の20分で、下表の6ケースについて自分の判断と戻す対象を書きます。
「次へ進む」は、次の小さい範囲での確認へ進む意味です。

| ケース | 正しい判断 |
| --- | --- |
| 2件とも表題だけ直り、本文は同じ | 次へ進む |
| 2件とも表題は正しいが、1件の本文も変わった | 止め、変更案を退けて旧版を維持 |
| 1件の旧版がなく比較できない | 止め、比較元を確保する |
| 直す表題の指定が1件分欠けている | 止め、指定を補う |
| 修正対象外の3件目も変わる案になっている | 止め、対象2件に戻す |
| 失敗案を直し、2件とも表題だけ変わり全条件に合う | 再比較後に次へ進む |

最後の10分で、正しい判断数を6で割って正答率を出します。
合格は6/6（100%）、かつ失敗・未確認の4ケースで拡大する判断が0件です。
止める4ケースでは、守る旧版または不足する旧版も4/4で特定します。
採用条件と旧版の名前が結び付かない場合は、指示を直して再採点します。
所要時間、誤答数、対象外の変更を許した件数を記録します。
40分と合格値はこの葉の試験案で、提供元の実測ではありません。
これは判断手順の点検であり、本体での変更・復旧の成功を示す実験ではありません。
