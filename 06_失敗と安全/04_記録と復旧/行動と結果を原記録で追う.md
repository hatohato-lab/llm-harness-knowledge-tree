## 1. 要点（一言と、根拠の段階と、使いどころ）

短い報告から、実際の行動と結果へ戻れるようにします。

根拠の段階：公式で確認。

原記録は、加工前に保存した出典や道具の結果です。
監査は、報告を原記録や実物と照合する作業です。
フックは、決めた出来事の前後に処理を動かす機能です。

賢いモデルは、複数の記録から矛盾を探す役に向きます。
軽いモデルは、決まった欄への整理に向きます。
どちらにも、記録項目と参照先を具体的に指定します。
調査、複数担当の作業、長い修正作業に向きます。
役割の分け方は設計案で、効果は未測定です。

## 2. 仕組み（なぜ効くか）

最終報告だけでは、誤りが生じた場所を追えません。
途中の入力、行動、結果をつなぐと、判断を見直せます。
公式は、実行の記録と実際の最終状態を区別します。
[Anthropicの評価指針](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

公式フックには、会話を識別する番号が渡されます。
道具の呼出し番号で、実行前と結果を対応付けられます。
[フックの共通入力](https://code.claude.com/docs/en/hooks#common-input-fields)

要約には、失敗や迷った理由が落ちることがあります。
事実の記録と、AIによる解釈を別の欄に置きます。
本人の意見も、AIの言い換えで上書きしません。
これは保存記事の原文保持案を広げた設計です。

DRIFTは、主張と途中の証拠を照合する研究方式です。
その論文は、誤った主張が後続へ伝わる問題を扱います。
最終回答だけでは分からない原因を調べています。
[DRIFTの論文](https://arxiv.org/html/2606.02060v2)

ここで残すのは、観測できる行動と結果です。
AI内部の思考をすべて取得できるとは扱いません。
同じAIが書き換えられる記録には、証拠として限界があります。

## 3. 使い方（手順と例）

1. 一回の作業に、他と重ならない番号を付けます。
2. 入力の出典、確認日、版を記録します。
3. 操作と結果を、同じ番号で結び付けます。
4. 事実、解釈、未確認を別々の欄にします。
5. 報告には、原記録の場所と該当箇所を付けます。
6. 重要な主張を抜き取り、原記録まで戻って照合します。

例は、公開資料を比べる作業の記録案です。

| 項目 | 記録例 |
| --- | --- |
| 作業番号 | 調査A・試行2 |
| 入力 | 公式ページ、確認日、資料の版 |
| 行動 | 指定した節を開いた |
| 観測した事実 | 対応する機能名が本文にある |
| AIの解釈 | 現在の作業にも使える可能性 |
| 未確認 | 手元の版で動くか |
| 原記録 | 保存先と該当行 |
| 成果 | 比較表の該当行 |

日次の一覧は、この記録を短くまとめて作ります。
要約後も、原記録への参照を残します。
記録が多いだけで、監査できるとは判断しません。
参照先を開けるかどうかまで確かめます。

許可された記録だけを読み、秘密の本文は複製しません。
保存期間は、再確認の必要性と情報の性質で決めます。
無期限保存や外部への同期は、この型の必須条件ではありません。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、45分の机上試験です。
AIの追加実行や道具の導入は不要です。
以下の数値目標は、この葉の試験案であり、提供元の実測値ではありません。

1. 5分で、上の公式評価指針から定義を三つ選びます。
2. 15分で、作業番号・主張・原文の場所・事実・解釈を三行に記録します。
3. 5分で、原記録を保ったまま、要約の一行だけを意図的に誤らせます。
4. 10分で、別の読み手が三つの参照先を開いて照合します。
   一人で試す時は答えを隠して読み直し、独立した検証とは区別します。
5. 10分で、誤った要約を訂正し、次の数値を記録します。

| 測る項目 | 分母と合格値 |
| --- | --- |
| 原記録の該当箇所まで戻れた主張 | 3件中3件 |
| 事実と解釈を別欄で扱えた主張 | 3件中3件 |
| 参照先が欠けた主張 | 3件中0件 |
| 意図的な誤要約を直せた件数 | 1件中1件、照合開始から5分以内 |

全条件を満たせば、手作業の記録形式は合格です。
満たさなければ、欠けた参照先や欄を直して同じ三件で再採点します。
自動記録の正確性や実運用の効果を確認したことにはなりません。
この試行案は、まだ実施していません。
