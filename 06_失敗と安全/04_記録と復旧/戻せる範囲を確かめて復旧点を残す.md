## 1. 要点（一言と、根拠の段階と、使いどころ）

変更の前に、戻せる対象と戻せない対象を分けます。
復旧点は、変更前へ戻るために残す保存状態です。

- 根拠の段階：公式で確認。
- Claude Codeの復旧機能と、その対象外を確認しました。
- 本体での確認：未確認。
- 推論が得意なモデルでも軽量モデルでも使えます。
- 指示は、対象、保存先、復旧方法まで具体化し、軽量モデルには復旧可否の表も渡します。
- 文書の一括修正や、実験的なコード変更に向きます。

## 2. 仕組み（なぜ効くか）

誤った状態を直し続けると、変更の原因が混ざります。
確認済みの状態を残すと、失敗前から試し直せます。
ただし、保存が覆う範囲を超えた操作は戻りません。

チェックポイントは、会話の節目に作る復旧点です。
Claude Codeは、編集道具による変更を記録します。
`/rewind`で、会話、編集、両方を選んで戻せます。
会話だけを戻すと、現在のファイルは残ります。

補助担当は、主担当とは別に作業するAIです。
次の対象は、同じ仕組みで戻ると考えません。

- 端末の命令で行った変更。
- メール送信など、外部サービスで済んだ操作。
- 人の手や、別の会話で加えた変更。
- 通常の補助担当による変更。
- 別の場所を指すリンク経由のファイル。

一部の補助手順には、復旧対象となる例外があります。
実際の対象は、使用版の公式説明で確かめます。
保存数と保存期間にも制限があります。
長期保存には、別の保存方法が必要です。
[復旧仕様の根拠](https://code.claude.com/docs/en/checkpointing)

## 3. 使い方（手順と例）

1. 変更する対象を列挙します。
2. 各対象を、ファイル、会話、外部状態に分けます。
3. 確認済みの元データと、保存先を対応させます。
4. 復旧対象外の操作を、今回の作業から分けます。
5. 異常時は追加変更を止め、現在の状態も残します。
6. 復旧範囲を選び、戻った実物を比較します。
7. 失敗した前提を直し、小さい変更で再開します。

元データは削除せず、変更案と分けて保存します。
保存記事にも、原文の退避と変更前の予備を残す提案があります。
退避先と元の場所を対応させ、戻す対象を追えるようにします。

今後の試行用の指示例です。
今回、この指示による復旧は実行していません。

```text
練習用文書の変更前データと、変更対象を対応させてください。
会話だけ戻る場合と、文書も戻る場合を区別してください。
外部操作は行わず、復旧できない対象を先に列挙してください。
失敗時は現状を保存し、復旧案と比較箇所を示してください。
```

会話の圧縮は、長い会話を短い要約へ置く処理です。
「圧縮でファイルが消える」という投稿もあります。
確認した記事では、独自の初期化処理が原因でした。
標準の圧縮がファイルを消した事例ではありません。
元の手順には外部送信も含まれます。
二段の自動保存を、そのまま採用する根拠にはしません。
[記事本文の確認箇所](https://qiita.com/kai_kou/items/199565c8c3a544c93261)

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、40分で終える紙上の復旧範囲テストです。
実際の削除、送信、差し戻しや、有料モデルの呼び出しは不要です。
最初の10分で、2節と公式仕様を読み、下表の答え欄を隠して写します。
次の20分で7ケースの復旧可否を答え、対象外なら別の保存方法も書きます。
通常ファイルの編集は、変更前の復旧点と保存データが残る場合を前提にします。

| 架空のケース | 正しい判断 |
| --- | --- |
| 現在の主担当が編集道具で通常ファイルを変更し、編集を戻す選択をする | 編集が復旧対象 |
| 同じ編集後に、会話だけを戻す選択をする | 現在のファイルは残る |
| 端末の命令でファイルを書き換える | 対象外。事前の複製や版管理で別に備える |
| 外部サービスでメールを送信する | 対象外。ファイルの復旧点では送信を取り消せない |
| 現在の主担当が触っていない別ファイルを人が編集する | 対象外。人の編集前の複製等が必要 |
| 通常の補助担当がファイルを編集する | 対象外。版管理等で別に備える |
| シンボリックリンク先のファイルを編集する | 対象外。リンク先の保存と個別の復旧方法が必要 |

最後の10分で答え合わせし、正しい判断数を7で割ります。
合格は7/7（100%）で、外部送信を戻せると誤認した件数が0です。
対象外の5ケースすべてに、別の備えか取消不能の理由を書けることも条件です。
誤答した対象と、足りなかった保存方法を記録して、指示表を直します。
40分と合格値はこの葉の試験案で、提供元の実測ではありません。
この紙上試行で分かるのは復旧範囲の理解であり、本体の動作確認ではありません。
将来の実機試験では、複製文書だけを使い、復旧後の内容を旧版と比較します。
復旧時間と残った変更数も記録し、報告だけで成功と数えません。
