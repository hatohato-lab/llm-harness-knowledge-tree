## 1. 要点（一言と、根拠の段階と、使いどころ）

画面の文章量ではなく、要求ごとの消費を数えます。

根拠の段階：公式で確認。
使用量表示と計上範囲を、公式文書で確認しました。
個別の削減率と、本体での実動作は未確認です。

トークンとは、AIが文章を処理する小さな単位です。
MCPとは、AIと外部の道具をつなぐ仕組みです。
フックとは、特定の操作時に動く補助処理です。

軽いモデル（軽量の言語モデル）には、固定した欄への転記と要求IDの重複候補抽出を任せます。
賢いモデル（高能力の推論モデル）には、再試行や分担先をまたぐ急増の原因候補を整理させます。
この役割分担は試すための設計案です。合計の計算は電卓などでも照合します。
指示は具体的にし、記録欄と比較期間を固定します。
指示例は「同じ1時間の記録から、要求ID、担当、入力、出力、再利用を表にし、重複を除いて合計」です。
消費が急増した調査や、長い定期作業のどの工程が増えたかを調べる場面に向きます。

## 2. 仕組み（なぜ効くか）

短い返答でも、入力には履歴や道具の結果が含まれます。
再試行や背景の要求も、画面の短さだけでは見えません。
原因別に数えると、費用が増えた段階を切り分けられます。

Claude Codeの `/usage` は、使用量を表示します。
金額表示は推定で、最終請求とは区別します。
端末内の内訳には、別端末の利用が含まれません。
この範囲は[公式の費用文書](https://code.claude.com/docs/en/costs)で確認しました。

「MCPは接続中ずっと一律に課金」は、未確認です。
道具の説明、結果、背景の要求を分けて調べます。
外部サービス自体の利用料も別に扱います。
「外部処理ならClaudeの消費ゼロ」も一般化できません。
外部から返った結果を読む処理は残り得ます。

## 3. 使い方（手順と例）

1. 作業前後の使用量と、計測時刻を控えます。
2. 主担当、分担先、定期処理の要求を分けます。
3. 入力、出力、再利用、再試行の量を記録します。
4. 同じ要求が重複していないか確認します。
5. 最も増えた要因を一つだけ選びます。
6. 同程度の作業で、その要因を変えて比較します。

費用台帳の例です。

| 欄 | 記録する内容 |
|---|---|
| 作業 | 作業名、時刻、担当名 |
| 要求 | 要求の識別番号、使用モデル |
| 消費 | 入力、出力、再利用、再利用の作成量 |
| 追加 | 再試行回数、外部道具の料金 |
| 結果 | 合否、修正回数、総時間 |
| 限界 | 記録漏れ、価格の確認日、計上対象 |

大量の全文読込みも、消費増の入口です。
先に検索し、必要な行だけ読む手順を候補にします。
長い結果は保存し、必要な部分を読み直します。
終了結果や重要なエラーを、短縮で隠さないでください。

機械的に止める場合は、操作前のフックを使えます。
対象の道具、文字数、例外、故障時の扱いを決めます。
Readとは、ファイルの内容を読む道具です。
Readだけを止めても、別の道具の読込みは残ります。
投稿の350行は独自の目安で、一般的な最適値ではありません。
拒否の仕組みは[公式フック文書](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)で確認しました。
読取り制限の設計と実動作は、別途検証が必要です。

## 4. 試し方（最初の一歩と測り方）

最初は40分で、下の架空台帳を紙や電卓で点検します。
準備5分、集計20分、答え合わせ15分です。新しいAI要求や課金は不要です。
全行は同じ1時間・同じモデルの記録で、再利用量は0と仮定します。
ここでの要求IDは、一送信を数える台帳上の番号です。
同じ操作の二重実行を防ぐ冪等性キーとは分けて扱います。
実際に再送された要求には新しい台帳番号を付け、同じ送信の再記録と区別します。

| 要求ID | 担当・理由 | 入力トークン | 出力トークン |
|---|---|---:|---:|
| r1 | 主担当の調査 | 100 | 20 |
| r2 | 分担先の調査 | 300 | 30 |
| r3 | 主担当の再試行 | 600 | 40 |
| r2 | 分担先の記録を二重に転記 | 300 | 30 |

正解を隠し、重複行を印で除外して、入力・出力・合計と最大の要求を答えます。
合格は、重複の検出が1/1件、誤除外が0/3件、入力1,000・出力90・合計1,090で
正解との差がいずれも0、最大の要求をr3の640トークンと答えられることです。
数値はこの葉で作った試験案で、提供元の実測値や削減率ではありません。

合格後に、許可された既存の実記録3件で同じ表を作り、公式表示と計上範囲を照合します。
私的な会話履歴の一括収集は不要です。机上試験だけでは実際の請求との一致は確認できません。
短縮を試す場合は、消費量と合否を並べ、重要なエラーが一つでも落ちたら不採用にします。
