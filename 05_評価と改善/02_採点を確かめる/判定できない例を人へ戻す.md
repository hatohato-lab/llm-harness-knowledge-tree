## 1. 要点（一言と、根拠の段階と、使いどころ）

**一言：証拠が足りない判定を、合格や不合格へ無理に押し込まない。**

根拠の段階：公式で確認。

モデル：軽量な汎用言語モデルでは、出典の有無など狭い基準で保留を使う。
推論型・高性能な汎用言語モデルでも、未知の分野や証拠不足は保留を認める。
指示：判定不能の条件と、戻す情報を具体に決める。
作業：根拠が欠けた調査や、境界例の多い採点に向く。

## 2. 仕組み（なぜ効くか）

判定不能は、合否を決めるだけの情報がない状態である。
公式記事は、情報不足なら不明を返せる設計を勧める。[1]

以下は、それを運用へ移す実務案である。
不明を別欄にすると、証拠不足と内容の欠陥を区別できる。
人は、足りない資料を補うか、基準を見直せる。
ただし、不明を増やすだけで採点の正確さは上がらない。
保留した量と、判定した範囲の誤りを一緒に測る。

## 3. 使い方（手順と例）

1. 合格、不合格、判定不能の三つを用意する。
2. 判定不能にする条件を、具体例で示す。
3. 不明の理由と、必要な追加情報を出させる。
4. 不一致や重要な保留を、人が確認する。
5. 追加資料の後に再採点し、最初の保留も残す。

例：報告書は出典を挙げるが、本文を取得できない。
「主張が偽」と断定せず、「裏付けは判定不能」とする。
ファイルが必須なのに未提出なら、提出条件は不合格にできる。
情報不足と要件違反を、採点項目で分けて扱う。

## 4. 試し方（最初の一歩と測り方）

最初は40分で、根拠付きの短い文章3件と、各文章から必要な証拠だけを隠した3件、計6件を用意する。
以下の時間・件数・成功基準は、この葉の学習用の提案であり、実測値ではない。

1. 10分で6件を作り、どの証拠を隠したかと、完全版の正解を人が先に記録する。
2. 5分で「必要な証拠がなければ判定不能」とする条件を固定する。
3. 15分で、同じモデル・同じ設定・同じ資料を使い、合否の二択指示と保留を許す三択指示を各6回、別の文脈で採点する。
4. 10分で二つの指示を比較し、不足の検出と不要な保留を別々に数える。

- 不足検出率は、証拠不足を正しく保留した件数 / 不足版3件。
- 不要保留率は、判定可能なのに保留した件数 / 完全版3件。
- 全体の保留率は、保留した件数 / 全6件。保留を分母から消さない。
- 完全版の正答率は、正しく判定した件数 / 3件。人の確認時間も残す。

練習の成功は、三択版で不足検出3/3件、不要保留0/3件、完全版の正答3/3件を満たし、
証拠不足のまま断定した件数が二択版より増えないこととする。
誤断定が両版とも0件なら、誤りを減らす効果は未確認と書く。
追加の課金・外部送信を避ける練習では、導入済みのローカルモデルを使う。
