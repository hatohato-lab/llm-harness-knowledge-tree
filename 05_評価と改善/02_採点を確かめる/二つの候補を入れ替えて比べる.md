## 1. 要点（一言と、根拠の段階と、使いどころ）

**一言：二案の順番を入れ替え、両方で勝つ案だけを選ぶ。**

根拠の段階：論文で確認。

モデル：複数の条件を比べられる推論型・高性能な汎用言語モデルから試す。
軽量な汎用言語モデルは、正確さなど狭い比較で人との一致を測る。
指示：比較基準と引き分け条件を具体的に書く。
作業：文章、回答、指示の変更前後の比較に向く。

## 2. 仕組み（なぜ効くか）

対比較は、二つの案のどちらが良いかを選ぶ方法である。
位置の偏りは、内容より提示順が判定へ影響する現象である。
MT-Bench論文は、順番による判定の反転を確認した。[1]
順番を交換し、両順で勝つ案だけを採る方法も示す。

入れ替えは、位置の影響を見つけるための手段である。
同じ誤解に基づき、両順で誤った案を選ぶ可能性は残る。
当時の実験結果を、今のモデルの性能とはみなさない。

## 3. 使い方（手順と例）

1. 同じ依頼から得た二案を用意する。
2. 作成者名と、どちらが新しい案かを隠す。
3. 基準を固定し、先にA、次にBで比較する。
4. 新しい採点の文脈で、B、Aの順に比較する。
5. 両順で同じ案が勝てば、勝者として記録する。
6. 反転したら、引き分けか人の再確認に回す。

例：説明の正確さと簡潔さを、変更前後で比べる。
「Aの勝ち・Bの勝ち・引き分け・判定不能」を使う。
名前を隠す手順は、ここでの実務上の追加案である。

## 4. 試し方（最初の一歩と測り方）

最初は45分で、短い説明文5組を比べる。
以下の時間・件数・成功基準は、この葉の学習用の提案である。
研究の実測値や、必要な標本数を示すものではない。

1. 10分で同じ問いへの二案を5組選び、正確さ・必要事項・簡潔さの基準を固定する。
2. 10分で、私がモデルの結果を見る前に各組の勝者か引き分けを記録する。
3. 15分で、同じモデル・同じ設定・同じ基準を使い、A→BとB→Aを別の文脈で各5回、計10回採点する。
4. 10分で、画面上のA/Bを元の案IDへ戻し、順序交換前の5判定と両順統合後の5判定を比べる。

- 反転率は、案IDで見た勝者が両順で変わった組数 / 5組。
- 確定勝者率は、両順で同じ案が勝った組数 / 5組。
- 人と違う確定勝者の件数、引き分け数、判定不能数を、それぞれ5組を分母に報告する。

練習の成功は、10/10回の結果を保存し、人と違う確定勝者が0/5組で、
確定勝者が3/5組以上あり、誤った勝者の件数が一方向だけの採点を超えないこととする。
確定勝者が少ないときは不成功として理由を調べ、無理に勝者を増やさない。
一方向でも誤りがなければ、誤りを減らす効果はこの試行では未確認と書く。
追加の課金・外部送信を避ける練習では、導入済みのローカルモデルを使う。

文学作品にも、AIと人の講評を比べた体験報告がある。[2]
その報告は、受賞に値する判断の違いを残している。
順序を入れ替える比較法の実証とは区別する。
文学賞の審査の妥当性は、この葉の論文では未確認である。
