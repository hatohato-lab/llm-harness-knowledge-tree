## 1. 要点（一言と、根拠の段階と、使いどころ）

**良い結果に届くまでの、品質と総負担を同時に測る。**

根拠の段階：公式で確認

トークンは、モデルが文章などを処理する単位です。
総費用は、初回だけでなく再試行や検査分も含む費用です。

賢いモデルと軽いモデルの使い分けを判断する際に役立ちます。
指示は、成功の定義と、記録する量を具体的にします。
反復する調査、分類、文書作成、開発に向きます。
モデルの選び方自体は、02_扱い方の担当範囲です。

## 2. 仕組み（なぜ効くか）

初回が安くても、手直しが多ければ総負担は増えます。
速さだけを測ると、不完全な仕事を有利に扱ってしまいます。
Anthropicは、正確さに加えて時間と使用量を測っています。
道具の呼出し回数とエラーも、改善の手がかりにしています。
出典は[道具を評価する公式記事](https://www.anthropic.com/engineering/writing-tools-for-agents)です。

品質、時間、費用は、まず別々に見るのが実務案です。
一つの点へ合算すると、重大な失敗が隠れる場合があります。
どの負担を受け入れるかは、本人の目的に照らして決めます。

## 3. 使い方（手順と例）

1. 同じ代表課題と、同じ合格条件を用意します。
2. モデル名、指示の版、設定、測定日を記録します。
3. 合否と、完了までの経過時間を記録します。
4. 再試行、採点、人の手直しも別欄へ記録します。
5. 実際の使用量が分かる場合だけ、金額へ換算します。
6. 品質条件を満たす候補の中で、総負担を比べます。

次は記録欄の例です。数値は空欄のまま始められます。

| 欄 | 記録する内容 |
|---|---|
| 品質 | 合格数／課題数、重大な失敗数 |
| 時間 | 最初の依頼から確認済み完了まで |
| 人の負担 | 手直しの分数、追加指示の回数 |
| 使用量 | 入力、出力、再試行、採点の処理量 |
| 金額 | 計算根拠のある総額、なければ未確認 |

定額プランの残量と、一回の金額を混同しません。
モデルの推論量を変える場合も、条件を記録して比べます。

## 4. 試し方（最初の一歩と測り方）

最初は50分で、短い分類課題三件を二つの条件で測る案です。
時間配分と採否の数値は、この葉の学習用の提案です。
今回の実測値や、普遍的な採用基準ではありません。

1. 10分で三件の短文と正解ラベルを人が決めます。Aは普段の設定、Bは指示だけを短くした設定とし、モデルと推論設定は固定します。
2. 20分でAとBを各三件、新しい会話で実行します。順序は一件目A→B、二件目B→A、三件目A→Bにし、入力、正解、出力形式は変えません。
3. 10分で六出力を採点します。正解ラベルと一致し、指定外の文がなければ合格です。完了までの秒数、人の修正分数、再試行回数、分かる範囲の入力・出力トークン数を各行に記録します。
4. 最後の10分で、合格数／3、重大な誤り数、三件の総秒数、手直し合計分数をAとBで比較します。費用は記録済み使用量と測定日の単価がそろう場合だけ算出し、分からなければ「未確認」とします。

測定の試運転は「六件すべてに合否・時間・手直し時間があり、使用量と金額の既知／不明が区別される」と成功です。
改善候補Bを残す条件は、合格数がA以上かつ2／3以上、重大な誤りゼロ、手直し時間が増えず、総秒数がAより10%以上短いことです。
費用が不明なら、費用削減まで成功したとは判断しません。
時間枠を超えた出力は未完了として記録し、50分で止めます。
成功が零件なら、成功一件あたり費用は計算できません。
三件では偶然を除けないため、各課題の値を保存し、候補の本採用前に別の課題でも繰り返します。

  - 私の作業で最適な設定は未確認です。
