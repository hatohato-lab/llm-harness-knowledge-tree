## 1. 要点（一言と、根拠の段階と、使いどころ）

望ましい入出力から指示の候補を作り、実行して選ぶ。
根拠の段階は「論文で確認」。

APEは、例から指示を生成し、採点で選ぶ研究手法である。
最初の指示をうまく書けない反復作業に向く。
分類、言い換え、定型の抽出などが対象になる。
例の共通規則を推論できるモデルには、候補作成を任せるとよい。
軽量な対話モデルを実行役にする場合は、具体的な入出力例と出力形式を示す。
候補作成の指示には、変えてよい条件と必ず守る条件を分けて書く。
これは運用上の提案であり、モデル間の効果は要検証。

## 2. 仕組み（なぜ効くか）

例には、口で説明しにくい出力の好みが含まれる。
複数の指示を逆算すると、解釈の違いを候補にできる。
対象モデルで実行すれば、相性を結果で比べられる。
文章が自然かどうかだけで選ばない点が要である。

原論文は、例の提示、候補生成、採点、選択を扱う。
原論文v2の4.1節は、比較条件を二つに分けて報告している。
実行時に入出力例を添えない条件（zero-shot）では、
24課題すべてで、人が作った指示と同等以上だった。
実行時に入出力例を添える条件（few-shot）では、
例だけを示す通常の方法にAPEの指示を加えると、24課題中21課題で同等以上だった。
この21課題は、人の指示との比較結果ではない。
ただし、当時のモデルと限定された課題での結果である。
任意の業務や現行モデルでの同じ効果は未確認。

採点自体に穴があると、望ましくない指示も選ばれる。
論文では、韻の課題で入力語を返す候補が残った。
同じ語は自分自身と韻を踏むため、採点を通ってしまう。
目的の意味と採点の一致も確認する必要がある。
根拠は[原論文の3節・4.1節・付録C.1](https://arxiv.org/html/2211.01910v2)である。

## 3. 使い方（手順と例）

次は原方式の考え方を借りた、小規模な試行例である。

1. 「記事から要点を3つ抜く」仕事を選ぶ。
2. 短い記事と望ましい出力を5組用意する。
3. 出力を再現できそうな指示を3案作らせる。
4. 各案を、同じ対象モデルと同じ条件で試す。
5. 正確さ、抜け、余分な補足を別々に採点する。
6. 有望な案を残し、必要なら言い換え案を加える。

候補作成の指示例は次のとおり。

```text
この入出力を説明できる指示を3案作ってください。
案ごとに、守らせたい条件の違いを書いてください。
```

候補作成に使う例と、最終確認の例は分ける。
詳しくは「保留問題で汎化を確かめる」を読む。

## 4. 試し方（最初の一歩と測り方）

以下の55分・件数・判定値は学習用の提案であり、原論文の実験規模ではない。
導入済みのモデルで、短い文から指定の項目を一つ抜く作業に絞る。

1. 10分で、候補作成用の入出力5組と、別の評価用10件を準備する。
   抜くべき文字列を正解表にし、余分な文や欠落は不合格と先に決める。
2. 10分で、5組だけを見せて指示を3案生成する。
3. 25分で、現行1案と生成3案を同じ評価用10件で1回ずつ試す（計40出力）。
   実行モデルの版、生成設定、入力順、出力形式、採点表を固定する。
4. 10分で、各案の完全一致した合格数÷10、欠落数、所要時間、呼出し回数を記す。
   現行より合格が2件以上増え、欠落が増えず、計測した実行時間が現行の1.5倍以内なら残す。

同点なら短い指示を残し、条件を満たさなければ現行を保つ。
55分で打ち切り、未完了は成功に数えない。
この10件は候補選択用なので、選んだ後の採用判断は新しい未使用例で行う。
高得点でも仕事の目的から外れた例は採用せず、例を加える条件も別に確かめる。
