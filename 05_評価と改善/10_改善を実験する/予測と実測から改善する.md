## 1. 要点（一言と、根拠の段階と、使いどころ）

改善案の予測を先に書き、実測との差から次の案を選びます。

- 根拠の段階：公式で確認。
- 確認範囲：一般的な改善手順です。AIでの効果は未確認です。
- モデル：推論を重視するモデルには、失敗原因の仮説と反証条件の吟味を任せます。
- 軽量モデルには、件数の転記や五欄への整理を任せ、原因の断定は人が確認します。
- 指示：目的は一文で示し、変える順番、固定する資料、予測値、採用条件は具体的に書きます。
- 作業：調査の出典漏れ、文章の必須項目漏れ、コード修正後の検査漏れを減らす工程改善に使います。

この使い分けは学習用の運用案で、モデル間の性能を実測した結論ではありません。

PDSAは、計画・実行・研究・反映を繰り返す型です。

## 2. 仕組み（なぜ効くか）

事前の予測があると、結果に合わせた後付け説明を減らせます。
予測との差は、改善案を支えた仮説を点検する材料です。
Deming Instituteは、結果の確認より理論の学習を重視します。
この説明は[公式のPDSA解説](https://deming.org/explore/pdsa/)で確認しました。

ここから先は、AIの工程改善へ当てはめる提案です。
指示を追加する前に、減るはずの失敗を一つ書きます。
成功した場合も、狙った理由で改善したかを調べます。
採点だけ上がり手直しが増えたなら、採用を保留します。

## 3. 使い方（手順と例）

1. 同じ失敗を一つ選び、変更前の結果を残します。
2. 変更箇所と、結果が変わる理由を書きます。
3. 合否と作業量の予測を、実行前に記録します。
4. 小さな課題で試し、予測と実測を並べます。
5. 採用、追加確認、不採用の理由を書きます。

例は、調査で出典の付け忘れが続く場合です。
「結論を書いた後に確認する」を変更候補にします。
「主張ごとに出典を先に置く」に変えて比べます。

| 記録欄 | 書く例 |
|---|---|
| 仮説 | 出典を先に置けば、付け忘れが減る |
| 変更 | 出典確認の順番だけを変える |
| 予測 | 付け忘れが減り、手直し時間は増えない |
| 実測 | 同じ課題の付け忘れ数と総時間 |
| 判断 | 仮説を残すか、何を次に調べるか |

測定、次の対象を選ぶ判断、変更の実施を分けて設計します。
各部分の入力と出力を確かめると、不調の場所を絞れます。
一つの処理で十分なら、担当を無理に増やしません。
これは[HumanLayerの設計手順](https://raw.githubusercontent.com/humanlayer/skills/main/plugins/design-control-loop/skills/design-control-loop/SKILL.md)にもある方法です。
繰り返す実行には、次回へ残す指摘と確認できる件数を決めます。

判断の記録には、何もしない案も入れます。
賛成と反対の根拠、前回の判断、見立てが変わる条件を書きます。
結果欄を空け、後で実際の結果を追記します。
保存記事の/decideは、この記録形式の応用例です。

結果がそろう前に、次の変更を重ねません。
変動への対応は、継続、再試行、旧版へ復帰に分けます。
これは観測と調整を分ける運用案です。
循環があるだけで安定するとは限りません。

## 4. 試し方（最初の一歩と測り方）

以下は50分で回す学習用の提案です。件数と数値基準は練習用で、実測値や普遍的な基準ではありません。
利用が許可された既存のモデル環境を使い、新しい導入は前提にしません。
この葉の作成ではモデル実験を実行していません。

1. 10分で、手元の短い非機密資料を3件選び、各資料から答えられる事実を5点ずつ決めます。各課題は「5点の説明に出典を付ける」とします。
2. 5分で、仮説・変更・予測・実測・判断の五欄を作ります。実行前に「出典漏れを15点中2点以上減らし、手直し込みの時間を旧版の1.1倍以内にする」と予測します。
3. 18分で、A「説明の後で出典を付ける」とB「出典を先に置いて説明する」を各課題で1回ずつ、計6回比べます。1回3分を上限にします。
4. 12分で、各条件の出典漏れ数/15点、事実誤り数/15点、合格課題数/3件を人が採点します。5点すべてが正しく、対応する出典がある課題だけ合格です。
5. 5分で、予測と実測を並べ、採用候補・保留・不採用の理由を五欄に残します。

モデル名・版、推論量、入力資料、出力する5点、道具、採点基準を固定し、出典を置く順番だけ変えます。
各実行は新しい会話にし、課題1・3はA→B、課題2はB→Aの順で試します。
途中で予測値を書き換えません。時間切れは不合格に数え、分母から外しません。
総時間は、各条件の生成時間と人の手直し時間の合計です。

Bの出典漏れがAより2点以上少なく、事実誤りが増えず、合格数が減らず、総時間がAの1.1倍以内なら採用候補です。
漏れが最初から0点なら改善の余地がないため、この仮説の効果は保留とします。
数値条件を満たしても、失敗が減った理由が予測と合うかを読み直します。
3件は手順を回せた証拠にとどめ、別の資料で再確認するまでは一般化しません。
AIの反省文の長さは、改善の成否に使いません。

一般理論自体は「01_原理」の範囲です。
この葉は、AIの変更案を実測で選ぶ運用を扱います。
