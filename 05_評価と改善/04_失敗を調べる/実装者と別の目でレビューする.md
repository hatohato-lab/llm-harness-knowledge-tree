## 1. 要点（一言と、根拠の段階と、使いどころ）

作った本人と別の担当が、成果物と合格条件を照合します。

レビューは、成果物の問題や要件の不足を点検する作業です。
文脈は、AIが判断のために参照できる情報です。

**根拠の段階：公式で確認**

賢いモデルは、動作の矛盾や複数箇所の影響確認に向きます。
軽いモデルは、具体的な規則との照合から試します。
指示には、対象、合格条件、指摘の根拠を具体的に書きます。
コード、調査報告、要件の多い文書の完成前に向きます。
モデルの使い分けは、本葉の試行案です。

## 2. 仕組み（なぜ効くか）

公式は、実装とレビューを別の文脈に分ける方法を示します。
検査役には、実装者の説明より成果物と基準を渡します。
これにより、作成時の思い込みを共有しにくくします。
ただし、誤りが独立になることや効果量は保証されません。
この説明の根拠は、[Claude Code公式の独立レビュー手順](https://code.claude.com/docs/en/best-practices#add-an-adversarial-review-step)です。

本葉では、対象一覧と適用規則を先に固定します。
これは、検査の抜けを人が把握するための運用案です。
複数担当を使うなら、担当する観点を分けます。
相手の結論は、各自の点検が終わるまで渡しません。

Superpowersの調査にも、小作業ごとに役を分ける例があります。
ここでは担当分けだけを参照し、製品全体の効果と分けます。

## 3. 使い方（手順と例）

1. 実装者の自己点検結果を、先に保存します。
2. 検査役へ、対象、差分、要件、検査済みの範囲を渡します。
3. 問題の場所、発生条件、根拠、重要度を返させます。
4. 各指摘を元の成果物や実行結果で確かめます。
5. 有効な指摘、誤指摘、未確認を分けて記録します。

例は、仕組みを理解するための試行用です。

```text
この成果物を、指定の要件に照らして点検してください。
実装者の説明を結論として引き継がないでください。
指摘には、場所、発生条件、要件の根拠を付けてください。
指摘なしも認めます。確認できない部分は未確認と書きます。
まず報告だけを作り、編集は行わないでください。
```

手動と自動の検査でも、同じ基準の版を使います。
Open Code Reviewは、対象と規則を先に選ぶ実装例です。
製品別の優劣や作者実験の数値は、ここでは一般化しません。

作業中に注意候補を知らせる補助担当も、応用の一つです。
通知がないことは、検査合格を意味しません。
報告件数の上限は、発見能力や検査の深さと区別します。

難しい判断だけ、強いモデルへ相談する変形もあります。
相談役が会話全体を読む場合、文脈は独立していません。
節目の相談と、説明を渡さない完成前点検を区別します。
軽い選別の後で詳しい点検を行うなら、選別の見逃しも測ります。

指摘の妥当性を、さらに別担当へ検査させる変形もあります。
ここでも、人数や二回無指摘を品質保証にはしません。
選別段階で落とした例を抜き取り、見逃しを調べます。

主担当が妥当な指摘を選び、修正後も同じ条件で点検します。
正誤に関わる欠落と、好みの書き換えは分けて報告します。
画面だけを確認して、裏側の動作まで合格にはしません。

## 4. 試し方（最初の一歩と測り方）

**最初の一歩は50分の比較に絞ります。**
以下の件数と合格線は学習用の提案で、研究の実測値ではありません。

1. 10分で、50行以内の過去の練習用変更1件と、要件5項目を選びます。成果物・差分・要件の版を固定します。
2. 10分で実装者の自己点検を行い、5項目の合否と問題一覧を保存します。
3. 10分で別の検査役に同じ差分と5要件を渡します。自己点検の結論や作成時の説明は渡さず、問題の場所・発生条件・根拠を求めます。
4. 15分で人が両方の指摘を成果物や既存の検査結果と照合し、有効・誤指摘・未確認に分けます。
5. 5分で、確認済み要件数÷5、自己点検にない有効指摘数、誤指摘数、合計時間を記録します。

成功条件は、要件の確認が5/5、追加の有効指摘が1件以上、誤指摘0件、合計50分以内です。
追加指摘が0件なら「効果を確認できず」と残します。無理に問題を作る指示へ変えません。
比較では成果物と要件を変えません。AIを比較する時は同じモデルと設定にし、変えるのはレビュー役の文脈だけです。
外部送信や新たな課金が必要なら、この最初の試行は手元の保存済みレビュー記録と人による照合で行います。

過去の小さな変更を一つ選び、検査役を一つ置きます。
自己点検だけの場合に加わった、有効な指摘を数えます。

追加で再現した不具合数、誤指摘数、確認時間を残します。
利用量と、確認できた対象の割合も測ります。

指摘を必ず作る指示は、架空の問題を生みやすくなります。
人数だけを増やしても、同じ見落としが残る場合があります。
別担当でも、同じ規則や元資料を共有することはあります。
独立性は、製品名ではなく渡した情報で判断します。

修正後に発生した手戻りも数え、指摘数だけで選びません。
