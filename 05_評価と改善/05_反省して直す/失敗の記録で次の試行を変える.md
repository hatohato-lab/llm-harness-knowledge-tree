## 1. 要点（一言と、根拠の段階と、使いどころ）

失敗の証拠から次の行動を決め、同じ課題を試し直す。

- 根拠の段階：論文で確認。
- 推論型モデルは、複数の失敗から原因候補を選ぶ役から試す。
- 軽量の指示追従型モデルは、決まった失敗形式の整理から試す。
- 指示は、証拠と次の変更を具体的に書かせる。
- 再実行できるコード、検索、模擬操作に向く。

モデルの使い分けは、この葉での実務上の提案です。
現在のモデルでの効果は未確認です。

反省記憶とは、試行の失敗と次の手を短く残す記録です。
Reflexionは、その記録を次の試行の入力へ加えます。
ここでは、同じ課題をやり直す範囲を扱います。
別の仕事へ使う教訓の管理は、教訓を蓄積する葉で扱います。

## 2. 仕組み（なぜ効くか）

「不合格」という結果だけでは、変更箇所が定まりません。
Reflexionは、行動の記録と評価結果を反省文へ変えます。
それを次の行動選択へ渡します。
変わるのはモデルへの入力で、学習済みの重みではありません。
これは論文第3節で確認しました。
[Reflexion論文](https://arxiv.org/html/2303.11366#S3)

ただし、反省文の原因説明は正解とは限りません。
論文は、自己生成テストの誤合格による悪化も分析しています。
難しいコード課題では、検査を除くと成績が下がりました。
評価と反省の組合せが重要だと分かります。
[論文の実験と限界](https://arxiv.org/html/2303.11366#S4.SS3)

実務では、原因を仮説として残すと試しやすくなります。
一度の変更を絞れば、どの変更が効いたかを見分けやすいです。
この運用上の効果は推論であり、私の作業では未確認です。

## 3. 使い方（手順と例）

1. 課題と成功条件を固定し、一度実行する。
2. テストや原資料で、失敗した箇所を確認する。
3. 事実、原因候補、次の変更を分けて書く。
4. その記録を渡し、同じ課題を再実行する。
5. 同じ確認方法で改善と悪化を調べる。

次は、引用元を取り違えた調査の記録例です。

```text
失敗の事実：記事Aの主張に、記事BのURLを付けた。
証拠：主張と該当段落が一致しない。
原因候補：要約した後で、URLをまとめて補った。
次の変更：主張を抜き出す時に、URLと段落を対で保存する。
再確認：主張ごとに、元の段落までたどれるか調べる。
```

「次は気を付ける」という反省だけでは再試行を変えられません。
行動を変える指示と、変化を確認する方法まで書きます。
確認できない原因には「仮説」と付けます。

論文の反省記憶は、モデル内部の学習とは異なります。
記録を次の入力へ渡さなければ、その試行では使われません。

反省の保存では、適用範囲と検証状態も記します。
元の結果への参照を付け、使えなかった助言も残します。
例えば、三資料のうち一件を要旨だけで比較した失敗です。
次の行動は、本文の該当節を読んでから比較することです。
この助言を恒久規則にせず、同じ比較の再試行に限定します。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は50分です。再現できる短い説明文の失敗を1件選びます。
以下の時間・件数・合格線は学習用の提案であり、論文の再現実験ではありません。

1. 10分で元の失敗文と資料を保存し、資料で判定できる必須要件を3個固定します。たとえば「対象を正しく書く」「条件を落とさない」「出典の段落が対応する」です。
2. Aは反省記録を渡さず、Bは第3節の形式の反省記録を渡します。同じモデル・元の失敗文・資料・要件から新しい会話で始め、各15分、最大2回だけ試し直します。モデル設定と採点者も固定します。
3. 最後の10分で各方式の最終文を同じ3要件で0/1採点します。要件充足率は「満たした数÷3」です。元の誤りの再発回数÷各方式の再試行数、新たな誤り件数、合計時間も残します。
4. Bが3/3を満たし、新たな誤り0件で、Aの最終点より高ければ次の小試行へ進みます。同点は反省記録の追加効果が未確認、Bが低ければ助言を見直します。50分で打ち切ります。

単に何度も試した効果と、反省記憶の効果を分けるため、試行回数と時間枠をそろえます。
原因仮説を確かめる証拠が増えたか、直った箇所と壊れた箇所も記録します。

誤った助言を採用した件数と、記録を再読する時間も測ります。
一件の成功は、記録の使いやすさを調べる材料にとどめます。
