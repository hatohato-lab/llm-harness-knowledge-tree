## 1. 要点（一言と、根拠の段階と、使いどころ）

説明のもっともらしさを、外部の事実と照合する。

根拠の段階：公式で確認

道具は、検索、計算、実行、画面観察などの外部処理を指す。
検証器は、決めた条件への適合を判定する仕組みを指す。

賢いモデルでも、未取得の実行結果は確認済みにできない。
軽いモデルには、読む結果と判定条件を具体的に渡す。
抽象指示は調査方針に使い、合否の指示は具体化する。
事実調査、計算、実装結果の確認に向く。

## 2. 仕組み（なぜ効くか）

文章の生成と、対象の実際の状態は別のものだ。
「保存した」という文だけでは、ファイルの存在は分からない。
保存先を読むと、説明とは別の証拠が得られる。
公式も、完了宣言と環境に残った結果を区別している。
[根拠：エージェントの評価](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

作る難しさと、確かめる難しさも同じではない。
条件を満たす文章を作るには、多くの選択が要る。
文字数だけなら、機械で数えて判定できる。
ただし、その文章が役に立つかは文字数では決まらない。
検証が容易になるのは、判定条件を明文化できる部分だ。

数学の研究では、生成と判定を別々に学習させている。
複数の解答を判定器で選ぶと、成績が改善する条件があった。
ただし、その判定器にも誤判定がある。
生成と検証の役割が違っても、検証の万能性は導けない。
[根拠：数学の検証器、第4.2節](https://arxiv.org/html/2110.14168v2)

| 得たい事実 | 道具から得られるもの | それだけでは分からないもの |
|---|---|---|
| 計算の結果 | 指定した式の実行値 | 式が目的に合うか |
| 画面の状態 | 実際の表示や操作結果 | 全利用者に使いやすいか |
| ファイルの保存 | 保存先の内容と更新状態 | 内容が正しいか |
| 出典の内容 | ページに書かれた主張 | 主張自体が真実か |

ReActは、外部検索を推論と交互に使う方式である。
論文は、取得した事実が推論の根拠を補うと報告した。
一方、役立つ検索結果を得られない失敗もあった。
道具を使うだけで、正答率が必ず上がるわけではない。
[根拠：ReAct、第3節](https://arxiv.org/html/2210.03629v3)

以上から、道具の結果にも対象と範囲が必要だと考える。
古いログや別の実行結果では、今回の状態を確かめられない。
これは上記資料から導く運用上の判断である。

## 3. 使い方（手順と例）

1. 確かめたい主張を一つ書く。
2. その主張を直接観測できる道具を選ぶ。
3. 結果と、結果からの解釈を分けて読む。
4. 判定できなかった範囲を残す。

例えば、一覧表の合計値を確認する場合を考える。
AIの説明と、元の数値から再計算した値を比較する。
値が一致しても、集計対象の選び方は別に点検する。

```text
合計値の根拠を確認してください。
元の数値、再計算した値、判定を分けてください。
集計対象が正しいかは、別の論点として残してください。
```

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、紙と手元の電卓で行う30分の試行である。
モデルへの送信や新しい契約は要らない。
次の「AIの回答案」は練習用の架空例で、実際の出力ではない。

| 問 | 元の数値 | AIの回答案 |
|---|---|---|
| 1 | 12、18、7 | 合計37、確認済み |
| 2 | 24、16、5 | 合計46、確認済み |
| 3 | 9、11、20 | 合計40、確認済み |
| 4 | 15、8、12 | 合計34、確認済み |
| 5 | 6、14、10 | 合計31、確認済み |

1. 5分で表を写し、「全3値の単純合計」を対象に固定する。
2. 10分で各問を電卓へ入力し、入力式と結果を記録する。
   回答案の値を電卓へ写すのではなく、元の3値から計算する。
3. 10分で各回答案を一致・不一致に分け、誤りを直す。
   正解は順に37、45、40、35、30である。
4. 5分で修正前後の正答数と、誤った確認済み報告を数える。
   値が正解と一致すれば1点、5問で5点満点とする。

成功は修正後5/5点、誤った確認済み報告が0件である。
修正前は2/5点、誤った確認済み報告は3件となる。
両方の数と所要時間を記録し、誤りが残れば入力式を点検する。
これは照合手順の操作確認で、モデルの性能比較ではない。

モデル比較は、別の50分の試行として行える。
利用済みの無料ローカルモデルか、同条件の保存回答が必要だ。
どちらもなければ、この比較は未実施と記録する。
5分で上の5問の元の数値だけを用意し、モデル名と設定を固定する。
20分で初回回答を1つ作り、同じ回答を2つの新しい会話へ渡す。
一方に自己点検を、他方に電卓の式と結果による照合を1回ずつ頼む。
入力する問題、回答形式、修正回数はそろえる。
15分で修正後の正答数と誤った確認済み報告を採点する。
10分で前後の得点、所要時間、使った式と観測値を記録する。
外部結果ありで5/5点、誤った確認済み0件なら採用候補だ。
得点が同じなら、この5問では正答数の改善を観測していない。
これは電卓結果を人が渡す比較で、自律的な道具利用の試験ではない。
