## 1. 要点（一言と、根拠の段階と、使いどころ）

「学んだ」は、何を書き換えたかで意味が変わります。
会話、記録、指示、モデル内部を分けて考えます。

根拠の段階：論文で確認

推論重視の大規模モデルにも、軽量の汎用モデルにも当てはまる区別です。
推論重視のモデルには、経験から共通点を探す役を任せる案があります。
軽量のモデルには、条件と直し方を具体的に渡す案があります。
ただし、この役割分担の効果は別途確認が必要です。
抽象指示で教訓を抽出し、具体指示で適用条件を残します。
繰り返す調査、文章整理、開発手順の理解に向きます。

## 2. 仕組み（なぜ効くか）

文脈は、モデルが今回の回答に使える情報です。
外部記憶は、会話の外へ保存し、後で読み直す情報です。
重みは、モデル内部の計算を決める多数の数値です。
ここでは、重みを更新する処理をモデル訓練と呼びます。
論文によっては、経験収集も訓練段階と呼びます。
名前だけで、重み更新の有無を決めることはできません。

| 変える場所 | 何が変わるか | 次回へ効く条件 |
| --- | --- | --- |
| 今の会話 | 訂正や例が文脈に加わる | その情報を参照できる |
| 外部記憶 | 事実や経験の記録が増える | 必要な記録を読み出す |
| 指示や手順 | 次に行う行動の案内が変わる | 対応する指示を読み込む |
| モデルの重み | 入力から出力を作る内部計算が変わる | 更新後のモデルを使う |

指示ファイルも、読み込まれれば文脈の一部になります。
記憶と指示の境界は、保存形式より内容の役割にあります。
事実の記録は「何が起きたか」を伝えます。
指示の更新は「次にどうするか」を伝えます。
この区分は、仕組みを理解するための整理です。

Reflexionは、反省文を次の試行へ渡す研究手法です。
論文は、重みを更新せず行動を変えると説明します。
ExpeLは、複数の経験から教訓を抽出する研究手法です。
こちらも、教訓と過去例を読み出して判断を変えます。
両者は、文章の利用による適応を示します。
モデル本体の再訓練を示す研究ではありません。

ACEも、重みではなく、経験をまとめた手順集を更新する研究です。
更新した手順集を次の入力へ渡すため、判断に使える情報が変わります。
これは[ACE論文の第2.1・3節](https://arxiv.org/html/2510.04618v3)と、
[公開実装の入力生成](https://github.com/ace-agent/ace/blob/main/ace/core/generator.py)で区別できます。

SkillRLは、手順集とモデル訓練を組み合わせる研究です。
手順を読む訓練に加え、成績を使う訓練も行います。
その成績を、手順ファイルの更新だけの効果に移せません。
根拠は[Reflexion](https://papers.nips.cc/paper_files/paper/2023/file/1b44b878bb782e6954cd888628510e90-Paper-Conference.pdf)、[ExpeL](https://arxiv.org/html/2308.10144v3)、[SkillRL](https://arxiv.org/html/2602.08234v1)です。

Claude Codeの公式文書も、記憶を文脈として説明します。
保存しただけで、正しい行動や改善が保証されるわけではありません。
参照は[記憶の公式文書](https://code.claude.com/docs/en/memory)です。

## 3. 使い方（手順と例）

改善の記事を読むとき、変更した場所を一つずつ確認します。
「使うほど賢くなる」だけでは、仕組みを判定しません。
保存物、読み出す時点、訓練の有無を確かめます。

例として、日付の誤読を訂正した場面を考えます。
会話に訂正を書けば、今回の判断材料が変わります。
記録へ残せば、後の作業で使える材料ができます。
手順へ直せば、日付確認を行うよう案内できます。
重みを変えるには、これらとは別に訓練処理が要ります。
これは説明用の例で、今回の実験結果ではありません。

## 4. 試し方（最初の一歩と測り方）

最初は30分で、変更場所を見分ける無料の手作業をします。
材料は下の架空事例6件と紙だけです。モデルの起動や訓練は不要です。

| 番号 | 架空事例 |
| --- | --- |
| 1 | 同じ会話で日付の誤読を訂正し、次の回答へ進む。 |
| 2 | 実際に起きた失敗を記録ファイルへ保存し、次回に検索して読む。 |
| 3 | 日付確認の手順ファイルを直し、次回開始時に読み込む。 |
| 4 | 訓練処理で重みを更新し、更新済みのモデルで次回を実行する。 |
| 5 | 失敗記録を保存したが、次回に読んだかは分からない。 |
| 6 | 記事には「使うほど賢くなる」とだけあり、変更場所の説明がない。 |

1. 5分で第2節の表を読み、次の答え合わせ欄を隠します。
2. 10分で各事例の「変わった場所」「次回へ効く条件」を書きます。
3. 10分で答え合わせをし、各欄1点、計12点で採点します。
4. 5分で誤答だけを直します。初回点と修正後点を別に残します。

答え合わせは、1＝今の会話・訂正が参照できること、
2＝外部記憶・必要な記録を読み出すこと、
3＝指示や手順・更新した手順を読み込むこと、
4＝重み・更新済みモデルを使うこと、
5＝外部記憶・読出しが未確認なので次回への効果も未確認、
6＝場所も経路も未確認、です。同じ意味なら1点とします。

成功は修正後12/12点で、5と6を改善済みと誤認しないことです。
これは仕組みの分類練習で、モデル性能の改善を証明する実験ではありません。
性能を測る次の段階では、同種課題で誤り再発数と読出し失敗数を分けます。
今回はこの練習も性能比較も実行していません。

任意の比較は別枠40分で、指示を変える場合だけに絞ります。
既存の無料ローカルモデルか、下の同条件の保存回答がなければ未実施です。
5分で「締切5日、訂正6日」という架空記録を写し、
同じ形で7日→8日、9日→10日、11日→12日の計4件を作ります。
10分で「最新の締切は何日か」と問い、15分でもう一度、
「訂正された日付を採用する」という手順を加えて同じ4問を試します。
各問は新しい会話にし、モデル・設定・記録本文を固定します。
最後の10分で正解と照合し、両条件の誤答数を0〜4件で数えます。
手順ありで誤答が減れば、この4問では改善、同数なら差は未確認です。
入力に手順を入れたかも4件それぞれ記録し、入力漏れは別に数えます。
ここで変えたのは指示であり、重みの訓練ではありません。
少数例の結果を他の課題の改善率とはみなしません。
