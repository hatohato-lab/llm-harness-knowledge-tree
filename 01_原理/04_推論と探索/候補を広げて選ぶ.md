## 1. 要点（一言と、根拠の段階と、使いどころ）

**候補を増やす力と、正しい候補を選ぶ力は別です。**

根拠の段階：論文で確認

探索は、複数の答えや途中の案を調べることです。
選別は、その候補を同じ基準で比べることです。

- 高性能な対話モデルでは、解法や設計の候補を比べます。
- 軽量な対話モデルでは、正解を検査しやすい小課題から試します。
- 抽象指示でも、選ぶ基準と探索の上限は具体化します。
- 具体指示は、計算、短いコード、原因候補の比較に向きます。

## 2. 仕組み（なぜ効くか）

最初の案を伸ばすだけでは、早い段階の誤りを残すことがあります。
別の候補を作ると、その道筋から離れる機会ができます。
ただし、正解が候補に入っても、選別で落とせば失敗です。

自己整合性は、複数の解き方の最終回答を集約する方法です。
論文では、答えの一致を使う方式が改善を示しました。
計算や常識推論の実験であり、全作業への保証ではありません。
[自己整合性の原論文](https://arxiv.org/html/2203.11171v4)

木探索は、途中の案を分岐させ、評価して戻る方式です。
Tree of Thoughtsは、この方式を言語モデルへ適用しました。
最終回答だけの多数決と、途中の分岐探索は区別します。
[木探索の原論文](https://arxiv.org/abs/2305.10601)

LATSは、候補探索に道具の結果や失敗記録を加える方式です。
コード実験では、生成したテストで候補を選びました。
最後は別の本来のテストで、選んだ1件を採点しました。
[LATSの実験条件](https://arxiv.org/html/2310.04406#S5.SS2)

pass@1は、この実験では最終候補1件の正答率です。
内部の候補生成が1回だけ、という意味ではありません。
同実験は8回の探索を行い、展開ごとに5候補を作りました。
単発の回答と比べる際は、総使用量も見る必要があります。

## 3. 使い方（手順と例）

1. 答えを選ぶ基準を、候補作成より先に決めます。
2. 候補数と使える時間を決めます。
3. 候補同士を、同じ資料やテストで比べます。
4. 選んだ候補を、選別に使わなかった問題で確かめます。

たとえば、文字列を整形する短い処理で比べます。
3案を作り、空文字や重複を含む同じ入力を渡します。
説明の上手さではなく、期待する出力との一致で選びます。
事実調査では、票数より一次資料との一致を優先します。
この手順は、論文の機構を小課題へ移した試行案です。

## 4. 試し方（最初の一歩と測り方）

最初の一歩は、35分の手作業で行う候補選びです。
紙かメモ帳を使い、モデルの呼び出しや課金は不要です。
課題は「文字の並びから重複を除き、最初に出た順を保つ」です。
候補は、A＝重複を除いて文字順に並べる、B＝隣り合う重複だけ除く、C＝左から見て初出の文字だけ残す、の3つです。
これらは用意した練習用の案で、モデルの生成結果ではありません。

1. 5分で仕様を読み、比較する基準を正解との完全一致に固定します。
2. 10分で選別用の `b,a,b` → `b,a` と空列→空列を各案で処理します。
3. 合格したテスト数が最大の案を1つ選びます。同点なら候補名の早い順に選びます。
4. 残り20分で、選び直さずに次の保留問題5件を採点します。

| 保留する入力 | 正解 |
| --- | --- |
| b,a | b,a |
| a,b,a | a,b |
| c,a,c,b | c,a,b |
| a,a,b | a,b |
| a,c,c | a,c |

最初の案Aをそのまま使った正答数と、選んだ案の正答数を、各5件で比較します。
さらに、3案のどれかが正解した件数と、選んだ案が正解した件数を分けて記録します。
手順の成功条件は、選んだ案が5/5件で正答し、最初の案より正答数が増え、35分以内に終わることです。
答え合わせは、Aが3/5件、Cが5/5件、3案のどれかが正解した件数は5/5件です。
正解が候補にあるのに選べなければ、選別基準かその適用を見直します。

この少数例は候補生成と選別を分ける操作の練習で、LLMの改善率の実証ではありません。
実際の回答で比較するときは、同じモデル・課題で単発と3候補を比べます。
正答数に加え、全候補の入力・出力の総使用量と所要時間も記録します。
任意の追試は、既に使える無料ローカルモデルか、同じ条件の保存済み3候補がある場合に行います。
仕様だけを渡して別々の会話で3案を得て、最初の案を単発側として残します。
モデルと版・生成設定・各回答の長さ上限を固定し、3候補側は上の選別2件だけで1案を選びます。
保留5件と正解は候補生成にも選別にも見せず、選んだ後に初めて採点します。
準備10分・生成20分・選別10分・保留採点15分の計55分を上限にし、未完了は未完了と記録します。
改善候補は単発より保留正答数が増えた場合です。同点なら正答数の改善は観察できず、追加使用量だけを記録します。
これは候補数を増やす予算の比較で、同じ総使用量での優劣ではありません。
使える環境や保存回答がなければ紙上練習までにし、少数例から一般的な改善率は推定しません。
